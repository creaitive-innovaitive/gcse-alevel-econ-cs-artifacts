Insertion Sort, Step by Step

Compare place and place + 1, and swap with a temp variable, walking each new item backwards through the sorted part of the list.

The big idea

Insertion sort builds a sorted list from the left. It takes the next item and walks it backwards through the sorted part, swapping with its left neighbour until that neighbour is no longer bigger. Then it moves on to the next item.

The steps

1. Treat the first item as a sorted list of one.

2. Take the next item (place + 1) and compare it with the item on its left (place).

3. If they are in the wrong order, swap them using temp, then step one place to the left and compare again.

4. Stop when the left neighbour is not bigger, or the front of the list is reached.

5. Repeat for every remaining item.

Best case

Already sorted: every item needs one comparison and no swaps, so the work grows in proportion to N: O(N).

Worst case

Reverse order: each item walks all the way to the front. About N² ÷ 2 swaps, so O(N²).

Swapping with temp

temp ← list[place]
list[place] ← list[place + 1]
list[place + 1] ← temp

Park one value in temp, overwrite it, then write temp back. Without temp, one value would be lost.

Versus bubble sort

Same swaps, different route

Both sorts fix a list using swaps of neighbouring items, so they look alike on paper. The difference is where they look and when they stop.

Bubble sort

Sweeps the whole unsorted part of the list from the left, comparing each neighbouring pair and swapping if they're the wrong way round. One sweep carries the largest remaining value to the far right, like a bubble rising. Then it starts again from the left, one place shorter each time.

The sorted part grows from the right-hand end, and every value inside it is already in its final position.

Insertion sort

Takes one new item at a time and walks it backwards through the part already sorted, swapping until the item on its left is no longer bigger. Then it stops and moves on to the next item.

The sorted part grows from the left-hand end, but its values are only sorted relative to each other. A later, smaller item can still push them along to the right.

Trace both on [7, 3, 9, 4, 1] and they make exactly the same number of swaps, 7. That's not a coincidence: each swap fixes exactly one pair that was out of order, and this list has 7 such pairs, so any adjacent-swap sort needs 7 swaps. What changes is how many comparisons it takes to find them.

Bubble sortInsertion sort
Comparisons on [7, 3, 9, 4, 1]109
Swaps on [7, 3, 9, 4, 1]77
Comparisons if already sorted10 (always all pairs, without a stop-early flag)4 (one per item, then it stops)
Sorted part grows fromthe rightthe left
Stops looking early?Only with a "no swaps this pass" flagYes, built in: the inner loop ends as soon as the neighbour is smaller

Insertion sort's advantage shows up on lists that are already nearly in order: each new item only has to travel a short way before the inner loop ends, so the work drops close to one comparison per item. Bubble sort has no such shortcut unless you add one. On a list in reverse order neither has any advantage, and both are slow on big lists, which is why the exam usually cares about the method, not the speed.

Examples are explained in general terms.

  
Sorting a hand of playing cards
Most people pick up one card at a time and slide it into the right place among the cards already held. That is insertion sort.
Use it for: explaining the algorithm in plain words.

  
Keeping a leaderboard in order
When a new score arrives, it is slotted into the sorted board. Only scores below it shift down, with no need to sort everything again.
Use it for: why it is quick when the data is nearly sorted.

  
Small parts inside faster sorts
Many standard library sorts switch to insertion sort for very short sections, because for small lists its low overhead beats fancier methods.
Use it for: evaluation: best for small or nearly sorted lists, poor for large random ones.

Q1 Describe 3 marks Describe how an insertion sort puts a list of numbers into ascending order.

    
ReminderSay where the sorted part is, what is compared and what happens when the order is wrong.

    
1. The first item is treated as a sorted list of one (the list is divided into a sorted and an unsorted part).
2. The next item is taken from the unsorted part and compared with the item on its left in the sorted part.
3. If it is smaller it is swapped (or shifted) backwards, repeating until the item on its left is not larger, then the next item is taken.
4. This is repeated until every item has been placed.

    
Common mistakeDescribing bubble sort: sweeping the whole list and carrying the largest value to the end.

  
Q2 Trace 4 marks Show the list [7, 3, 9, 4, 1] after each item has been inserted, and state the total number of swaps.

    
Start: 7 | 3 9 4 1 → insert 3: [3, 7, 9, 4, 1] (1 swap)
Insert 9: [3, 7, 9, 4, 1] (0 swaps)
Insert 4: [3, 4, 7, 9, 1] (2 swaps)
Insert 1: [1, 3, 4, 7, 9] (4 swaps)
Total swaps = 1 + 0 + 2 + 4 = 7.

    
Common mistakeCounting comparisons instead of swaps. Every swap fixes one pair that was out of order.

  
Q3 Explain 3 marks Explain why an insertion sort is quicker on a nearly sorted list than on a list in reverse order.

    
1. On a nearly sorted list each new item is already close to or in its correct place, so it needs very few comparisons and swaps.
2. On a reversed list every new item must be moved all the way to the front of the sorted part.
3. So the work is close to N for a nearly sorted list but about N² ÷ 2 for a reversed list.
