19.1.5 Comparing algorithms: Big O notation

How to describe, in one short expression, how the time or memory an algorithm needs grows as the amount of data grows.

1 · Definition

What Big O notation is

Big O notation is a mathematical notation used to describe the performance or complexity of an algorithm in relation to the time taken or the memory used for the task. It describes the worst-case scenario.

It answers one question: as N (the number of items of data) gets bigger, how fast does the time or memory needed grow?

Time complexity

How the number of steps (and so the time) grows as N grows. Written like O(N) or O(N²).

Space complexity

How the amount of memory the algorithm needs grows as N grows. Same notation, different question.

Why not just time it in seconds?Seconds depend on the computer, the language and what else is running. Big O counts steps against N, so it compares the algorithms, not the machines. A fast laptop running an O(N²) algorithm still loses to a slow phone running O(log N) once N is big enough.

Worked example: searching a list

You want to find a name in a list of N names using a linear search: check item 1, then item 2, and so on. Pick where the name sits and watch the steps.

Big O uses the worst caseThe first item might be found in 1 step, but Big O quotes the worst case: all N items checked. So a linear search is O(N) even though it sometimes gets lucky.

For space complexity the syllabus only asks for O(1) and O(N). The textbook writes the exponential one as O(2N) in places. It means 2 to the power N, not 2 × N.

3 · Space complexity

Each order of space complexity, explained

Space complexity asks how much memory the algorithm needs as N grows. The syllabus gives two orders.

O(1)Constant space

Always uses the same amount of memory to do the task. Example: any algorithm that just uses variables, such as d = a + b + c.

d ← a + b + c
O(N)Linear space

Memory grows in direct proportion to N. Example: any algorithm that uses arrays, such as a loop that calculates a running total of values input to an array of N elements.

DECLARE values : ARRAY[1:N] OF INTEGER
total ← 0
FOR i ← 1 TO N
   INPUT values[i]
   total ← total + values[i]
NEXT i
Memory used as N grows
NO(1) cellsO(N) cells (array + total + counter)
Common mistakeA loop that runs N times but only ever stores one running total uses O(1) space, and takes O(N) time. Space counts memory, time counts steps. Read the question to see which one is asked.

Going further (not required for 9618)Recursion also uses memory: each call adds a stack frame. A recursive factorial of N stacks N frames, so it needs O(N) space even though it declares no array. Useful in an evaluation point about recursion vs iteration.

    Examples are explained in general terms. Real systems add many details.

    Looking up a name in a sorted contacts list

    A binary search halves the list each time, so even a list of a million names needs about 20 comparisons. A linear search could need a million.

    Use it for: O(log N) versus O(N), and why sorted data is worth keeping.

    Sorting a large table in a database

    Simple sorts such as bubble sort take about N² steps, which becomes far too slow for millions of rows. Better algorithms such as merge sort take about N log N.

    Use it for: comparing sorting algorithms by order of growth.

    Checking every pair of users

    Comparing each user with every other user in a network takes about N² steps. Doubling the number of users makes the work four times bigger.

    Use it for: the doubling test and O(N²).

    Planning a delivery route

    Trying every possible order of stops grows extremely fast with the number of stops. Real systems use shortcuts that give good routes, not guaranteed best ones.

    Use it for: exponential and factorial growth, and why some problems are hard.

    Memory for an array of readings

    A program that stores one reading per sensor needs memory in proportion to the number of sensors, O(N). A program that keeps only a running total needs the same small amount of memory however many readings arrive, O(1).

    Use it for: space complexity.

    Activity 19Q: answers with explainers

    Open each question for a model answer, a diagram and the reasoning behind it. Mark points are colour-coded like a mark scheme.

    Q1 a) Using a diagram, describe the structure of a binary tree 3–4 marks
    • A tree is made of nodes, joined by branches. The top node is the root.
    • Each node has at most two children: a left child and a right child.
    • Each node holds data plus a left pointer and a right pointer (null if there is no child). A node with no children is a leaf.
    • In an ordered tree: smaller values go to the left of a node, larger to the right, which is why binary trees are quick to search.
    Exam tipLabel root, node, leaf, left pointer and right pointer on your diagram. A bare circle-and-lines sketch with no labels usually loses marks.
    Q1 b) Using a diagram, describe the structure of a linked list 3–4 marks
    • A linked list is a set of nodes. Each node has a data field and a pointer field.
    • The pointer holds the address/index of the next node, so nodes need not be next to each other in memory.
    • A start pointer identifies the first node. The last node's pointer is null to mark the end.
    • Nodes are inserted or deleted by changing pointers, so no data has to be shifted, and the list can grow or shrink.
    Exam tipIn a linked list you can only reach a node by following pointers from the start. That is why searching it is O(N), never O(log N).
    Q2 a) Explain what is meant by a dictionary data type 2 marks

    A dictionary is an abstract data type (ADT) made of pairs: each pair has a key and a value. The key is used to find the value, so you look items up by key, not by position.

    Real-life picture: a phone contacts list. The name is the key, the number is the value. In the textbook's example the student ID is the key and the name is the value (27 → Leon, 78 → Ahmad, 64 → Susie). Keys must be unique.

    Exam tip"Explain" needs two ideas: what it stores (key/value pairs) and how it is used (key finds the value). One half alone gets one mark.
    Q2 b) Show how a dictionary can be constructed from a linked list 4+ marks

    Make each node of the linked list hold a key, a value and a pointer. The nodes are linked in the same way as an ordinary linked list.

    To look a value up: start at startPointer, compare each node's key with the key wanted, and follow the pointer if they differ. When the keys match, return that node's value. If you reach the null pointer the key is not in the dictionary.

    Add a pair: take a free node, fill in key and value, and link it in. Delete a pair: point the previous node at the node after it.

    TYPE dictNode
   DECLARE key     : INTEGER
   DECLARE value   : STRING
   DECLARE pointer : INTEGER
ENDTYPE

DECLARE myDictionary : ARRAY[0:19] OF dictNode
DECLARE startPointer     : INTEGER   // first node in use
DECLARE heapStartPointer : INTEGER   // first free node

    Link to Big OEvery lookup walks the list from the start, so this dictionary is O(N) to search, just like a linear search. Real dictionaries in programming languages use a hash table to get close to O(1), which is why they are so fast.
    Q3 Compare the performance of a linear search and a binary search using Big O notation 4 marks

    Model answer, colour-coded by mark point:

    A linear search has time complexity O(N), where N is the number of items in the list. The time taken is directly proportional to N: if the list doubles, the worst-case time doubles. A binary search has time complexity O(log N). The time taken goes up only by a small, fixed amount each time the list doubles, so it increases linearly as the number of items increases exponentially. So a binary search becomes far more time-efficient than a linear search as the list gets bigger (though it needs the data to be sorted).

    6 · Toolkit

    Spotting the order of any algorithm

    Four rules that cover almost everything

    If the code…Then it is…
    does a fixed number of steps, whatever N is (even a loop of 10)O(1)
    halves the problem each time (halving N, or discarding half the list)O(log N)
    has one loop that goes through the N items onceO(N)
    has a loop inside a loop, both over NO(N²)
    calls itself twice, each with a slightly smaller problem (or tries every combination)O(2N)

    Loops one after another add (N + N is still O(N)). Loops inside each other multiply (N × N = O(N²)).

    Real-world examples

    Picture N as the number of things you have to deal with.

    O(1)

    Constant: a locker

    You know the locker number, so you walk straight to it. 10 lockers or 10,000, one step. A light switch, reading array[5] and the even/odd check work the same way.

    In an exam: "the time taken does not depend on the number of items."

    O(log N)

    Logarithmic: guess my number

    Guess a number from 1 to 1,000 and I answer "higher" or "lower". Always guess the middle and you need at most 10 guesses. Double the range to 2,000 and it costs just one more guess. Finding a word in a paper dictionary by opening near the middle is the same idea.

    In an exam: binary search, on sorted data only.

    O(N)

    Linear: finding a name on an unsorted register

    Nobody has sorted the register, so you read down it until you find the name. A register twice as long takes twice as long. Reading a book page by page and totalling a shopping receipt are the same.

    In an exam: linear search, running total.

    O(N²)

    Quadratic: everyone shakes hands with everyone

    10 people in a room: about 100 handshake attempts (45 distinct pairs, still growing with N²). Invite 20 people and it is about 400, four times as many. Bubble sort compares every item against many others in the same way.

    In an exam: bubble sort and insertion sort.

    O(2N)

    Exponential: the combination lock

    A lock with N on/off switches has 2N combinations. Each extra switch doubles the tries. 10 switches: 1,024. 30 switches: over a billion. It is why brute-forcing long passwords is impractical. Recursive Fibonacci behaves like this because each call spawns two more.

    In an exam: recursive Fibonacci; "adding one item doubles the time".

    Space

    Space: sticky note vs photocopied register

    Adding three numbers needs a sticky note with three numbers and an answer: O(1), however big the numbers are. Copying a whole class register onto a new sheet needs space that grows with the class size: O(N).

    Common mistakes

    MistakeWriting "O(N) means it takes N seconds." It means the number of steps grows in proportion to N. Never quote seconds.
    MistakeSaying binary search works on any list. It needs the data sorted first. Sorting costs time too.
    MistakeReading O(2N) as "2 × N". Doubling per item is very different from doubling once.
    MistakeGiving best case. A linear search that finds the item first time is not O(1). Big O is worst case.

    Top tips

    Tip 1Learn the table cold: five time orders with one example each, two space orders with one example each. Most marks are direct recall.
    Tip 2For "describe the performance", give the notation and a plain-English sentence about how time changes as N grows.
    Tip 3Use the words "as the number of items increases". Answers that skip the link to N do not earn the mark.
    Tip 4Marks match the question: 1 mark for the notation, 1 for the meaning, extra marks for the comparison.
    Tip 5Link back to what you know: nested loops in sorts, halving in binary search, one pass in linear search.
    Tip 6Say "worst case" once in any answer. It shows you know what Big O measures.

    Top tips

    • Big O describes the worst case as N gets large. Ignore constants and smaller terms: N² + N is O(N²).
    • Say "as N increases". Complexity is about growth, not about one particular run time.
    • Use the doubling test. Doubling N doubles the steps for O(N), quadruples them for O(N²), and adds one step for O(log N).
    • Loops after each other add; loops inside loops multiply.
    • Do not confuse time and space complexity. Name which one the question asks for.
