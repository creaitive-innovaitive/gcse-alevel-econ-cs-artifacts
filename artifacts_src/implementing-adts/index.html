Implementing ADTs from ADTs
A-Level Computer Science · 9618 · Topic 19.1.4

Implementing one ADT from another ADT

Every ADT is built on top of simpler data types. Learn how arrays and records become linked lists, how a linked list becomes a dictionary, and how to write the pseudocode the exam asks for. Includes live simulators, Activity 19O and 19Q answers, exam questions and tips.

The idea

Building on what already exists

An abstract data type (ADT) is a collection of data together with the operations used on that data. Its definition can refer to other data types, so a new ADT can be implemented from an existing one.

The textbook's examples: a linked list is defined using an INTEGER pointer and an item. A stack, queue and binary tree are all defined using existing types. A dictionary can be defined using a linked list. Each layer hides the one beneath it, so the user of a dictionary never sees pointers.

Dictionary key and value pairs, find a value from its key
Linked list ordered items joined by pointers
Array of records TYPE with an item and a pointer
Primitive types INTEGER, STRING, BOOLEAN
Exam wording"Implement" in these questions means "show how it can be built from". Name the underlying structure, name the pointers or variables that make it behave like the ADT, and show the operation working.
Linked list

A linked list built from an array of records

Define a record type with the data and a pointer, then make an array of them. The array indexes are the memory addresses. The pointer holds the index of the next node, and -1 means null (no next node).

TYPE linkedList
   DECLARE item    : INTEGER
   DECLARE pointer : INTEGER
ENDTYPE

DECLARE myLinkedList    : ARRAY [0:11] OF linkedList
DECLARE heapStartPointer : INTEGER   // first free node
DECLARE startPointer     : INTEGER   // first node in the list
DECLARE index            : INTEGER
Two linked lists in one arrayThe array holds two chains. The list in use starts at startPointer. The unused nodes form the heap, a second chain starting at heapStartPointer. Adding a node moves it from the heap to the list. Deleting moves it back.

Activity 19O answer

Declare a linked list for names, set up 30 nodes, then store and display names. Every node starts on the heap, chained to the next.

TYPE linkedList
   DECLARE item    : STRING
   DECLARE pointer : INTEGER
ENDTYPE

DECLARE names : ARRAY [0:29] OF linkedList
DECLARE startPointer, heapStartPointer, newPtr, current : INTEGER

// set up: empty list, all 30 nodes on the heap
startPointer ← -1
heapStartPointer ← 0
FOR index ← 0 TO 28
   names[index].pointer ← index + 1
NEXT index
names[29].pointer ← -1

PROCEDURE addName(newName : STRING)     // add at the front
   IF heapStartPointer = -1
      THEN OUTPUT "List full"
      ELSE
         newPtr ← heapStartPointer
         heapStartPointer ← names[newPtr].pointer
         names[newPtr].item ← newName
         names[newPtr].pointer ← startPointer
         startPointer ← newPtr
   ENDIF
ENDPROCEDURE

PROCEDURE displayNames()
   current ← startPointer
   WHILE current <> -1
      OUTPUT names[current].item
      current ← names[current].pointer
   ENDWHILE
ENDPROCEDURE

The program stores names by calling addName (for example three times with input from the user) and then calls displayNames. Names appear in reverse order of entry because each new node is added at the front.

Dictionary

A dictionary built from a linked list

A dictionary is an ADT of key and value pairs. The key is used to find the value. Each key can appear only once, keys are unordered, and the same value can appear more than once.

A dictionary is not an ordered list, so a linked list can be part of its definition. One linked list stores the keys. A parallel array stores the value for each key at the same position. To get a value you search the key list for the key, then read the value at that index.

TYPE linkedList
   DECLARE item    : STRING
   DECLARE pointer : INTEGER
ENDTYPE

TYPE dictionary
   DECLARE keys   : ARRAY [0:19] OF linkedList
   DECLARE values : ARRAY [0:19] OF STRING
ENDTYPE

DECLARE myDictionary     : dictionary
DECLARE heapStartPointer : INTEGER
DECLARE startPointer     : INTEGER
DECLARE index            : INTEGER

Same key twice

Adding a key that is already there must replace its value, not create a second entry. That is what "each key can only appear once" means in practice.

Dictionary or set?

A set holds unique values. A dictionary holds unique keys, but the values can repeat. That is the textbook's distinction.

Dictionaries in the languages you use

The syllabus languages provide a built-in dictionary type, so you rarely build one by hand. You still need to know it can be built from a linked list.

Python

studentdict = {
  "Leon": 27,
  "Ahmad": 78,
  "Susie": 64
}

VB.NET

Dim studentdict As _
  New Dictionary(Of String, Integer)
studentdict.Add("Leon", 27)
studentdict.Add("Ahmad", 78)
studentdict.Add("Susie", 64)

Java no longer uses Dictionary. It is implemented with a hash table, for example new Hashtable<Integer, String>() with put(27,"Leon").

Other ADTs

Stack, queue and binary tree from existing types

The same pattern repeats. Pick an array (or linked list), add the pointers the ADT needs, and the operations follow.

ADTBuilt fromExtra variables or fields
Stack1D arraya topPointer; push and pop both work at the top (LIFO)
Queue1D arrayfrontPointer and rearPointer; add at the rear, remove from the front (FIFO)
Linked listarray of recordsitem and pointer per node, plus startPointer and heapStartPointer
Binary treearray of recordseach node has leftPointer, item, rightPointer, plus rootPointer
Dictionarylinked list + arraykeys in the list, values in a parallel array at the same index

    Exam questions

    Exam-style questions with model answers

    Tick each mark point you included before opening the answer in your head. Colours match the mark scheme points.

    Q1 · Implement a stack from an array 4 marks Describe

    Describe how a stack ADT can be implemented using an array.

    Reminder"Describe" needs a few distinct points. Mention the array, the pointer, and what push and pop do to the pointer.
    • 1Use a 1D array to hold the stack data, with a fixed maximum size
    • 2Use a variable (top pointer) to record the index of the top item
    • 3Push: check not full, increase the top pointer, store the item at that index
    • 4Pop: check not empty, read the item at the top pointer, decrease the top pointer

    Common mistake: forgetting the full and empty checks. They are often worth a mark.

    Q2 · Dictionary from a linked list 3 marks Describe

    A dictionary ADT is to be implemented using a linked list. Describe how a value is found from a given key.

    • 1Start at the node the start pointer refers to
    • 2Compare each node's key with the given key, following the pointer to the next node until a match or the null pointer is reached
    • 3On a match, return the value stored at the same index in the values array (otherwise report "not found")
    Mark tipMention the "not found" case. Without it you cannot reach full marks on a search description.
    Q3 · Write the pseudocode 5 marks Write

    A linked list stores integers using nodes with item and pointer. Write a function countNodes() that returns how many items are in the list.

    FUNCTION countNodes() RETURNS INTEGER
   DECLARE total, current : INTEGER
   total ← 0
   current ← startPointer
   WHILE current <> -1
      total ← total + 1
      current ← myLinkedList[current].pointer
   ENDWHILE
   RETURN total
ENDFUNCTION
    • 1Function header and RETURNS INTEGER
    • 2Total initialised to 0 and current set to startPointer
    • 3Loop until the null pointer (-1)
    • 4Increment the total inside the loop
    • 5Move to the next node using the pointer, and return the total

    Common mistake: using a FOR loop over the whole array. That counts free heap nodes too.

    Real world

    Where these structures show up

    Browser back button

    A stack of visited pages. Back pops the most recent one.

    In an exam: use it to justify why a stack (LIFO) suits the task.

    Print queue

    Jobs are added at the rear and printed from the front, in arrival order.

    In an exam: name front and rear pointers and FIFO.

    Phone contacts or a Python dict

    Look up a number from a name. Names are unique keys, numbers are values.

    In an exam: link it to key, value and "each key once".

    Music playlist

    Songs joined one after the next, easy to insert in the middle without shifting the rest.

    In an exam: advantage of a linked list: insert and delete by changing pointers.

    File system

    Folders branch into folders and files, like a tree of nodes with pointers.

    In an exam: use it as a tree example, with root and child nodes.

    Undo in an editor

    Each action is pushed on a stack. Undo pops the latest one.

    In an exam: tie push and pop to the stack's top pointer.
    Top tips

    What to remember in the exam

    Name the partsSay which type it is built from (array, linked list), then name the pointers. "Array plus a top pointer" earns more than "an array".
    Keep the two pointers apartFor a linked list, startPointer is the list in use and heapStartPointer is the free nodes.
    Null is -1Loops walk the list until the pointer is -1, never until the end of the array.
    Dictionary, in one lineKeys in a linked list, values in a parallel array at the same index, each key stored once.
    Common slipDeclaring the dictionary type with a mix of two structures in one line. Write the TYPE with separate DECLARE lines for keys and values.
    Command words"Show how" and "describe how" need working and detail. "State" needs only the name.
