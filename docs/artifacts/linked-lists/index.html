Linked Lists

How an array-based linked list actually works: nodes, pointers, the heap of free space, and the find / insert / delete algorithms — built for A2 Paper 3 theory and Paper 4 practical, with real Cambridge exam questions and mark schemes built in.

Coursebook 19.1 & 10.4 Syllabus 9618 Paper 3 & Paper 4

01 The idea

A linked list is an Abstract Data Type (ADT): a collection of data plus a defined set of operations on it — find, add, delete — where you only care what those operations do, not how they're built underneath.

Every item in the list ("node") is stored together with a pointer to the next item. A startPointer marks the first node. The last node's pointer is set to −1, a null pointer — the signal that there's nothing further to follow.

Fig. 1 — a populated linked list (coursebook Fig. 10.12)
Why bother? Linked lists keep data in order (usually ascending or descending) without having to shuffle every element along, the way inserting into the middle of a sorted array would. You only ever rewrite two pointers.

02 Anatomy: two arrays, one heap

On the exam, a linked list is almost always implemented using two parallel 1D arrays of the same fixed size — never real pointers/memory addresses. This is the detail examiners repeatedly say candidates skip.

  • myLinkedList — holds the actual data, one item per index.
  • myLinkedListPointers — holds, for the same index, the index of the next node in the list.
  • startPointer — the index of the first node in the ordered list (−1 if the list is empty).
  • heapStartPointer — the index of the first free slot. The unused array positions are themselves managed as a linked list — the "heap" or free list.

Together, one array index represents one node: the data at myLinkedList[i] and the "next" pointer at myLinkedListPointers[i] belong to the same node.

Worked example

Starting from an empty 12-element list and adding 27, 19, 36, 42, 16 in that order — using the ordered insert algorithm in section 4, which walks the chain to splice each new node into its correct sorted position — the arrays end up like this:

Read it by following the chain: startPointer is 4 → index 4 holds 16, whose pointer is 1 → index 1 holds 19, pointer 0 → 27, pointer 2 → 36, pointer 3 → 42, pointer −1 → end of list. So the pointers give the list order 16, 19, 27, 36, 42 — genuinely ascending, even though the items sit at whatever array index they happened to be allocated from the heap (in insertion order: 27, 19, 36, 42, 16). Only the pointer chain decides the list's real order; the physical array positions are just where each node's data happens to live.

This is not insertion sort. Insertion sort (section 19.1.2) repeatedly shifts array elements along to sort a whole array that's already fully populated. This is different: it's inserting one new node into a linked list that is already sorted, by walking pointers to find the right gap and splicing it in — no data ever moves, only two pointers change. That's the entire point of using a linked list for ordered data instead of a plain array.

To set up an empty linked list

DECLARE myLinkedList ARRAY[0:11] OF INTEGER
DECLARE myLinkedListPointers ARRAY[0:11] OF INTEGER
DECLARE startPointer : INTEGER
DECLARE heapStartPointer : INTEGER
DECLARE index : INTEGER

heapStartPointer ← 0
startPointer ← -1        // list empty

FOR index ← 0 TO 11
    myLinkedListPointers[index] ← index + 1
NEXT index

// the heap is itself a linked list of every free space,
// set up once when the linked list is initialised
myLinkedListPointers[11] ← -1
// the final heap pointer is -1: no further free links

for index in range(12):

03 Finding an item

To search, start at startPointer and follow the chain of "next" pointers — comparing the data at each index — until either the item is found, or the pointer reaches −1 (not found). This is not a linear scan of the array from index 0; you must follow the links.

FUNCTION find(itemSearch) RETURNS INTEGER
    DECLARE found : BOOLEAN
    CONSTANT nullPointer = -1
    itemPointer ← startPointer
    found ← FALSE

    WHILE (itemPointer <> nullPointer) AND NOT found DO
        IF myLinkedList[itemPointer] = itemSearch
          THEN
            found ← TRUE
          ELSE
            itemPointer ← myLinkedListPointers[itemPointer]
        ENDIF
    ENDWHILE

    RETURN itemPointer
    // returns the item's index, or -1 if not found
ENDFUNCTION
def find(itemSearch):
    found = False
    itemPointer = startPointer
    while itemPointer != nullPointer and not found:
        if myLinkedList[itemPointer] == itemSearch:
            found = True
        else:
            itemPointer = myLinkedListPointers[itemPointer]
    return itemPointer
Trace tables come up constantly. Examiners set questions that ask you to trace itemPointer step by step. Practise writing out the pointer value on every loop iteration — not just the final answer.

04 Inserting an item

Adding an item always means the same first step — take the next free slot from the heap and write the data there. What changes is where the new node gets stitched into the chain.

Ordered insert — keeps the list sorted

This is the version behind the worked example in section 2. It walks the pointers to find the correct sorted position (the node whose data is just larger than the new item), then splices the new node in between its predecessor and that node — no data ever moves, only pointers.

PROCEDURE linkedListAdd(itemAdd)
  IF heapStartPointer = nullPointer
    THEN
      OUTPUT "Linked list full"
    ELSE
      // claim the next free slot from the heap
      newPointer ← heapStartPointer
      heapStartPointer ← myLinkedListPointers[heapStartPointer]
      myLinkedList[newPointer] ← itemAdd

      IF (startPointer = nullPointer) OR (itemAdd < myLinkedList[startPointer])
        THEN
          // itemAdd is the new smallest value: insert at the head
          myLinkedListPointers[newPointer] ← startPointer
          startPointer ← newPointer
        ELSE
          // walk the chain to find the node just before the right spot
          previousPointer ← startPointer
          currentPointer ← myLinkedListPointers[startPointer]
          WHILE (currentPointer <> nullPointer) AND (myLinkedList[currentPointer] < itemAdd) DO
              previousPointer ← currentPointer
              currentPointer ← myLinkedListPointers[currentPointer]
          ENDWHILE
          // splice the new node in between previousPointer and currentPointer
          myLinkedListPointers[newPointer] ← currentPointer
          myLinkedListPointers[previousPointer] ← newPointer
      ENDIF
  ENDIF
ENDPROCEDURE
def linkedListAdd(itemAdd):
    global startPointer, heapStartPointer
    if heapStartPointer == nullPointer:
        print("Linked list full")
        return

    # claim the next free slot from the heap
    newPointer = heapStartPointer
    heapStartPointer = myLinkedListPointers[heapStartPointer]
    myLinkedList[newPointer] = itemAdd

    if startPointer == nullPointer or itemAdd < myLinkedList[startPointer]:
        # itemAdd is the new smallest value: insert at the head
        myLinkedListPointers[newPointer] = startPointer
        startPointer = newPointer
    else:
        # walk the chain to find the node just before the right spot
        previousPointer = startPointer
        currentPointer = myLinkedListPointers[startPointer]
        while currentPointer != nullPointer and myLinkedList[currentPointer] < itemAdd:
            previousPointer = currentPointer
            currentPointer = myLinkedListPointers[currentPointer]
        # splice the new node in between previousPointer and currentPointer
        myLinkedListPointers[newPointer] = currentPointer
        myLinkedListPointers[previousPointer] = newPointer

Simple insert — the version given in the coursebook

The AS-level pseudocode Cambridge actually gives (coursebook Table 19.16) is simpler: it skips the search entirely and always makes the new item the new head of the list. Fine for a stack-like structure, but it will not keep the list sorted — each new item just lands in front of whatever was already there.

PROCEDURE linkedListAdd(itemAdd)
  IF heapStartPointer = nullPointer
    THEN
      OUTPUT "Linked list full"
    ELSE
      tempPointer ← startPointer          // keep old start pointer
      startPointer ← heapStartPointer     // new node claims this slot
      heapStartPointer ← myLinkedListPointers[heapStartPointer]  // heap moves on
      myLinkedList[startPointer] ← itemAdd
      myLinkedListPointers[startPointer] ← tempPointer
  ENDIF
ENDPROCEDURE
def linkedListAdd(itemAdd):
    global startPointer, heapStartPointer
    if heapStartPointer == nullPointer:
        print("Linked list full")
        return

    tempPointer = startPointer              # keep old start pointer
    startPointer = heapStartPointer         # new node claims this slot
    heapStartPointer = myLinkedListPointers[heapStartPointer]  # heap moves on
    myLinkedList[startPointer] = itemAdd
    myLinkedListPointers[startPointer] = tempPointer
Exam trap: always check heapStartPointer = −1 (list full) before writing to the heap. Cambridge mark schemes give a method point specifically for this check — in both versions above.

05 Deleting an item

Deleting doesn't shuffle data along, unlike a plain array. Instead: find the node, splice it out by pointing its predecessor directly at its successor, then return the freed index to the front of the heap so it can be reused.

PROCEDURE linkedListDelete(itemDelete)
  IF startPointer = nullPointer
    THEN
      OUTPUT "Linked list empty"
    ELSE
      index ← startPointer
      WHILE myLinkedList[index] <> itemDelete AND (index <> nullPointer) DO
          oldIndex ← index
          index ← myLinkedListPointers[index]
      ENDWHILE

      IF index = nullPointer
        THEN
          OUTPUT "Item ", itemDelete, " not found"
        ELSE
          // unhook the node and return its slot to the heap
          tempPointer ← myLinkedListPointers[index]
          myLinkedListPointers[index] ← heapStartPointer
          heapStartPointer ← index
          myLinkedListPointers[oldIndex] ← tempPointer
      ENDIF
  ENDIF
ENDPROCEDURE
def linkedListDelete(itemDelete):
    global startPointer, heapStartPointer
    if startPointer == nullPointer:
        print("Linked list empty")
        return

    index = startPointer
    oldIndex = None
    while myLinkedList[index] != itemDelete and index != nullPointer:
        oldIndex = index
        index = myLinkedListPointers[index]

    if index == nullPointer:
        print("Item", itemDelete, "not found")
    else:
        # unhook the node and return its slot to the heap
        tempPointer = myLinkedListPointers[index]
        myLinkedListPointers[index] = heapStartPointer
        heapStartPointer = index
        myLinkedListPointers[oldIndex] = tempPointer
2022 examiner report, verbatim: "candidates are asked to explain how the simplified linked list structure could be improved... expected to explain how the spaces where data had been deleted could be re-used using a free list pointer." That free list is the heap above — know the term.

06 Linked list vs. plain array

Sorted arrayLinked list
Insert in orderShift every element after the insertion pointRewrite two pointers
DeleteShift every element after the deleted oneRewrite two pointers; slot returned to heap
Direct access by positionO(1) — array[i]O(n) — must follow pointers from the start
Memory overheadNone extraSecond array needed, purely for pointers
Fixed capacity?YesYes (both use fixed-size arrays here)
Data structure typeStatic — generally fixed in sizeDynamic — freedom to expand/contract as nodes are added or removed

This trade-off — cheap insert/delete vs. expensive direct access — is exactly what several past-paper "explain the advantage / disadvantage" questions are testing. Say why, not just that it's faster or slower.

Paper 3 mark-scheme language. The "static vs dynamic" framing is the actual wording Cambridge examiners credit (9618/32, Oct/Nov 2023, Q9(b) — see Exam corner): "a linked list is a dynamic data structure / not restricted in size... has greater freedom to expand or contract by adding or removing nodes as necessary", vs. "an array is a static data structure, generally fixed in size... when the array is full, [it] cannot be extended any further." Use those exact terms — static, dynamic, fixed in size — rather than vaguer phrasing like "more flexible".

9618/32 · Paper 3 · Oct/Nov 2023 · Question 9(b) 2 marks

Following on from pseudocode to set up and push onto an array-based stack: "Justify the use of a linked list instead of an array to implement a stack."

Show mark scheme

One mark for a correct point about each structure (max 2):

Linked list — a linked list is a dynamic data structure, not restricted in size; it has greater freedom to expand or contract by adding or removing nodes as necessary; it allows more efficient editing using pointers (instead of moving the data).

Array — an array is a static data structure, generally fixed in size; when the array is full, the stack cannot be extended any further.

Why this is a 2-mark trap Most candidates only argue one side (just the linked list, or just the array) and cap themselves at 1 mark. The mark scheme awards a point per structure — you need a correct statement about both to get full marks, and the reward words are dynamic/static, not looser phrasing like "more flexible".

How this connects to the rest of this page This is the exact same array-of-records pattern as sections 2–5, just with two next-pointers per node (left/right) instead of one — so NowPtr moving via .LeftPtr or .RightPtr is doing the same job as itemPointer ← myLinkedListPointers[itemPointer] in the find function in section 3. Notice BinTree[NowPtr].Data — this only works because each array element is a record (a user-defined type bundling LeftPtr/Data/RightPtr together), not a single value, so .Data picks out just one field of that record.
9618/43 · Paper 4 · May/June 2025 · Question 3 29 marks total

A full practical question: build a linked list using Object-Oriented Programming. A Node class stores TheData and NextNode; a LinkedList class stores HeadNode and implements InsertNode(), RemoveNode() and Traverse(). This is the Paper 4 equivalent of everything in sections 2–5 — same node/pointer idea, built as objects instead of two parallel arrays.

(a) Write the Node class with its constructor [4]; its two get methods [3]; and SetNextNode() [2].

(b) Write the LinkedList class with its constructor [2]; InsertNode(), which creates a new node, uses SetNextNode() to point it at the current head, then replaces the head with it [4]; Traverse(), concatenating every node's data into one string [3]; and RemoveNode(), which finds and unhooks the first node matching a given value [6].

(c) Insert the values 10, 20, 30, 40, 50, call Traverse(), remove 30, then call Traverse() again and screenshot the output. [5]

Show example mark-scheme code (Python) 
class Node:
    def __init__(self, NodeData):
        self._TheData = NodeData   # Integer
        self._NextNode = None      # Node

    def GetData(self):
        return self._TheData

    def GetNextNode(self):
        return self._NextNode

    def SetNextNode(self, pNextNode):
        self._NextNode = pNextNode


class LinkedList:
    def __init__(self):
        self._HeadNode = None      # Node

    def InsertNode(self, NodeData):
        TheNode = Node(NodeData)
        TheNode.SetNextNode(self._HeadNode)
        self._HeadNode = TheNode

    def Traverse(self):
        ReturnValue = ""
        CurrentNode = self._HeadNode
        while CurrentNode != None:
            ReturnValue = ReturnValue + str(CurrentNode.GetData()) + " "
            CurrentNode = CurrentNode.GetNextNode()
        return ReturnValue

    def RemoveNode(self, DataToRemove):
        if self._HeadNode == None:
            return False
        elif self._HeadNode.GetData() == DataToRemove:
            self._HeadNode = self._HeadNode.GetNextNode()
            return True
        Found = False
        CurrentNode = self._HeadNode
        while not(Found) and CurrentNode != None:
            if (CurrentNode.GetNextNode()).GetData() == DataToRemove:
                CurrentNode.SetNextNode(CurrentNode.GetNextNode().GetNextNode())
                Found = True
            else:
                CurrentNode = CurrentNode.GetNextNode()
        return False

CreateList = LinkedList()

CreateList.InsertNode(50)
ReturnValue1 = CreateList.Traverse()

# ReturnValue2: "50 40 20 10 "
Why the output isn't 10, 20, 30, 40, 50 InsertNode() always points the new node at the current HeadNode and then replaces it — exactly the "simple insert" pseudocode from section 4, translated into OOP. That means every insert goes to the front of the list, so inserting 10 then 20 then 30 then 40 then 50 produces the list 50, 40, 30, 20, 10 when traversed — the official mark scheme's own expected output. If you expected ascending order here, you're thinking of the ordered insert from section 4, which this exam question deliberately doesn't ask for.
The thread connecting all three questions above: every single one is really testing the same node/pointer idea from section 1 — a static array-of-records version (Paper 3, Q11), an abstract justify-the-choice version (Paper 3, Q9), and a fully object-oriented version (Paper 4, Q3). Learn the concept once, and recognise it under each of these three disguises.

08 Glossary

Node
One item of data stored together with a pointer to the next item — on paper, one shared array index across myLinkedList and myLinkedListPointers.
Start pointer
Index of the first node in the ordered list; −1 when the list is empty.
Null pointer
A pointer value (conventionally −1) that is not a valid array index, marking the end of a chain.
Heap / free list
The set of unused array positions, itself managed as a linked list of available slots via a heapStartPointer.
Abstract Data Type (ADT)
A collection of data plus a defined set of operations on it (e.g. find, add, delete), independent of how it's implemented underneath.
Traversal
Following the chain of pointers from the start pointer to visit every node in order.
