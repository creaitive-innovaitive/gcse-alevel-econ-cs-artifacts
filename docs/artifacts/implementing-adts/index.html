Implementing ADTs from ADTs
A-Level Computer Science · 9618 · Topic 19.1.4

Implementing one ADT from another ADT

Every ADT is built on top of simpler data types. Learn how arrays and records become linked lists, how a linked list becomes a dictionary, and how to write the pseudocode the exam asks for. Includes live simulators, Activity 19O and 19Q answers, exam questions and tips.

The idea

Building on what already exists

An abstract data type (ADT) is a collection of data together with the operations used on that data. Its definition can refer to other data types, so a new ADT can be implemented from an existing one.

The textbook's examples: a linked list is defined using an INTEGER pointer and an item. A stack, queue and binary tree are all defined using existing types. A dictionary can be defined using a linked list. Each layer hides the one beneath it, so the user of a dictionary never sees pointers.

Dictionary key and value pairs, find a value from its key
Linked list ordered items joined by pointers
Array of records TYPE with an item and a pointer
Primitive types INTEGER, STRING, BOOLEAN
Exam wording"Implement" in these questions means "show how it can be built from". Name the underlying structure, name the pointers or variables that make it behave like the ADT, and show the operation working.
Linked list

A linked list built from an array of records

Define a record type with the data and a pointer, then make an array of them. The array indexes are the memory addresses. The pointer holds the index of the next node, and -1 means null (no next node).

TYPE linkedList
   DECLARE item    : INTEGER
   DECLARE pointer : INTEGER
ENDTYPE

DECLARE myLinkedList    : ARRAY [0:11] OF linkedList
DECLARE heapStartPointer : INTEGER   // first free node
DECLARE startPointer     : INTEGER   // first node in the list
DECLARE index            : INTEGER
Two linked lists in one arrayThe array holds two chains. The list in use starts at startPointer. The unused nodes form the heap, a second chain starting at heapStartPointer. Adding a node moves it from the heap to the list. Deleting moves it back.

Add and delete names, then press Next step to walk through exactly which pointers change. Amber rows are free heap nodes. Struck-through names are old data that is no longer reachable.

Activity 19O answer

Declare a linked list for names, set up 30 nodes, then store and display names. Every node starts on the heap, chained to the next.

TYPE linkedList
   DECLARE item    : STRING
   DECLARE pointer : INTEGER
ENDTYPE

DECLARE names : ARRAY [0:29] OF linkedList
DECLARE startPointer, heapStartPointer, newPtr, current : INTEGER

// set up: empty list, all 30 nodes on the heap
startPointer ← -1
heapStartPointer ← 0
FOR index ← 0 TO 28
   names[index].pointer ← index + 1
NEXT index
names[29].pointer ← -1

PROCEDURE addName(newName : STRING)     // add at the front
   IF heapStartPointer = -1
      THEN OUTPUT "List full"
      ELSE
         newPtr ← heapStartPointer
         heapStartPointer ← names[newPtr].pointer
         names[newPtr].item ← newName
         names[newPtr].pointer ← startPointer
         startPointer ← newPtr
   ENDIF
ENDPROCEDURE

PROCEDURE displayNames()
   current ← startPointer
   WHILE current <> -1
      OUTPUT names[current].item
      current ← names[current].pointer
   ENDWHILE
ENDPROCEDURE

The program stores names by calling addName (for example three times with input from the user) and then calls displayNames. Names appear in reverse order of entry because each new node is added at the front.

Dictionary

A dictionary built from a linked list

A dictionary is an ADT of key and value pairs. The key is used to find the value. Each key can appear only once, keys are unordered, and the same value can appear more than once.

A dictionary is not an ordered list, so a linked list can be part of its definition. One linked list stores the keys. A parallel array stores the value for each key at the same position. To get a value you search the key list for the key, then read the value at that index.

TYPE linkedList
   DECLARE item    : STRING
   DECLARE pointer : INTEGER
ENDTYPE

TYPE dictionary
   DECLARE keys   : ARRAY [0:19] OF linkedList
   DECLARE values : ARRAY [0:19] OF STRING
ENDTYPE

DECLARE myDictionary     : dictionary
DECLARE heapStartPointer : INTEGER
DECLARE startPointer     : INTEGER
DECLARE index            : INTEGER

Same key twice

Adding a key that is already there must replace its value, not create a second entry. That is what "each key can only appear once" means in practice.

Dictionary or set?

A set holds unique values. A dictionary holds unique keys, but the values can repeat. That is the textbook's distinction.

A dictionary in Python

Python has a built-in dictionary type, so you rarely build one by hand. You still need to know it can be built from a linked list.

studentdict = {
    "Leon": 27,
    "Ahmad": 78,
    "Susie": 64
}
studentdict["Ahmad"]        # 78, found from the key
studentdict["Ahmad"] = 80   # same key again replaces the value
Other ADTs

Stack, queue and binary tree from existing types

The same pattern repeats. Pick an array (or linked list), add the pointers the ADT needs, and the operations follow.

ADTBuilt fromExtra variables or fields
Stack1D arraya topPointer; push and pop both work at the top (LIFO)
Queue1D arrayfrontPointer and rearPointer; add at the rear, remove from the front (FIFO)
Linked listarray of recordsitem and pointer per node, plus startPointer and heapStartPointer
Binary treearray of recordseach node has leftPointer, item, rightPointer, plus rootPointer
Dictionarylinked list + arraykeys in the list, values in a parallel array at the same index

    Exam questions

    Exam-style questions with model answers

    Tick each mark point you included before opening the answer in your head. Colours match the mark scheme points.

    Q1 · Implement a stack from an array 4 marks Describe

    Describe how a stack ADT can be implemented using an array.

    Reminder"Describe" needs a few distinct points. Mention the array, the pointer, and what push and pop do to the pointer.
    • 1Use a 1D array to hold the stack data, with a fixed maximum size
    • 2Use a variable (top pointer) to record the index of the top item
    • 3Push: check not full, increase the top pointer, store the item at that index
    • 4Pop: check not empty, read the item at the top pointer, decrease the top pointer

    Common mistake: forgetting the full and empty checks. They are often worth a mark.

    Q2 · Dictionary from a linked list 3 marks Describe

    A dictionary ADT is to be implemented using a linked list. Describe how a value is found from a given key.

    • 1Start at the node the start pointer refers to
    • 2Compare each node's key with the given key, following the pointer to the next node until a match or the null pointer is reached
    • 3On a match, return the value stored at the same index in the values array (otherwise report "not found")
    Mark tipMention the "not found" case. Without it you cannot reach full marks on a search description.
    Q3 · Write the pseudocode 5 marks Write

    A linked list stores integers using nodes with item and pointer. Write a function countNodes() that returns how many items are in the list.

    FUNCTION countNodes() RETURNS INTEGER
   DECLARE total, current : INTEGER
   total ← 0
   current ← startPointer
   WHILE current <> -1
      total ← total + 1
      current ← myLinkedList[current].pointer
   ENDWHILE
   RETURN total
ENDFUNCTION
    • 1Function header and RETURNS INTEGER
    • 2Total initialised to 0 and current set to startPointer
    • 3Loop until the null pointer (-1)
    • 4Increment the total inside the loop
    • 5Move to the next node using the pointer, and return the total

    Common mistake: using a FOR loop over the whole array. That counts free heap nodes too.

    Paper 3 · 9618/32 Oct/Nov 2023, Q9(b) 2 marks Justify

    Justify the use of a linked list instead of an array to implement a stack.

    Reminder"Justify" means give a reason and tie it to the stack. One mark per developed point.

    Scheme: one mark for a linked list point and one for an array point (max 2).

    • LLA linked list is a dynamic data structure, not restricted in size
    • LLIt can expand or contract by adding or removing nodes as necessary
    • LLEditing is more efficient using pointers instead of moving the data
    • ArrayAn array is a static data structure, generally fixed in size
    • ArrayWhen the array is full, the stack cannot be extended any further

    Advice: you need one point from each side to reach 2/2. Contrast the two structures in the same sentence. "Linked lists are dynamic" alone is a description, not a justification.

    Paper 3 · 9618/31 Oct/Nov 2023, Q10(c) 2 marks Compare and contrast

    Compare and contrast the queue and stack Abstract Data Types (ADT).

    ReminderCompare means similarities, contrast means differences. Give at least one of each.

    Scheme: any two of these four points (max 2).

    • 1A queue is FIFO and a stack is LIFO (data leaves a queue in the order received, a stack in reverse order)
    • 2Both ADTs can vary in size (indeterminate length)
    • 3A stack pushes and pops at the same end; a queue enqueues and dequeues at opposite ends
    • 4A stack has one moveable pointer, a queue has two

    Advice: a table or "whereas" sentence keeps both sides of every point visible. Mention the pointers: that links straight back to how each is implemented.

    Paper 3 · 9618/31 and 32 Oct/Nov 2021, Q10(b) and (c) 5 marks Explain, Identify

    (b) Explain the reasons why a stack is a suitable ADT to implement recursion. [3]
    (c) Identify two ADTs other than a stack. [2]

    • 1(b) A stack is a LIFO data structure
    • 2(b) Each recursive call is pushed onto the stack and popped as the function ends
    • 3(b) This enables backtracking or unwinding, maintaining the required order (max 3)
    • 4(c) Linked list
    • 5(c) Queue, or binary tree (two correct ADTs for 2 marks)

    Advice: the three marks in (b) are three links in one chain: what is stored, why LIFO matters, what that gives you. The mark scheme for (c) lists linked list, queue and binary tree. Do not list data types such as array or record.

    Paper 4 style · Queue as a linked list of nodes 11 marks Show, Write

    Cambridge 9608 Paper 4, as printed in the Cambridge A Level textbook's end-of-chapter questions. The session is not given in the extract, and this version of the mark scheme is my own worked answer.

    A queue ADT has the operations create queue, add item to queue and remove item from queue. It is implemented as a linked list of nodes, each with data and a pointer to the next node. Nodes are stored in DECLARE Queue : ARRAY[1:10] OF Node, where Node has Name : STRING and Pointer : INTEGER. A pointer of 0 means null.

    (a) These operations are carried out: CreateQueue, AddName("Ali"), AddName("Jack"), AddName("Ben"), AddName("Ahmed"), RemoveName, AddName("Jatinder"), RemoveName. Show the final state of the queue. [3]

    • 1Ali then Jack are removed from the front (FIFO)
    • 2Final order from head to tail: Ben, Ahmed, Jatinder
    • 3Nodes drawn linked in that order, with the last pointer null

    (b)(i) Show the value of HeadPointer, TailPointer, FreePointer and every node's Pointer straight after CreateQueue. [4]

    • 4HeadPointer = 0 and TailPointer = 0 (queue is empty)
    • 5FreePointer = 1 (first free node)
    • 6Pointers of nodes 1 to 9 are 2 to 10 (each linked to the next)
    • 7Pointer of node 10 = 0 (end of the free list)

    (b)(ii) Complete the procedure AddName(NewName). [4]

    PROCEDURE AddName(BYVALUE NewName : STRING)
   IF FreePointer = 0
      THEN
         Report Error               // no free nodes
      ELSE
         CurrentPointer ← FreePointer
         Queue[CurrentPointer].Name ← NewName
         FreePointer ← Queue[FreePointer].Pointer
         Queue[CurrentPointer].Pointer ← 0
         IF HeadPointer = 0
            THEN HeadPointer ← CurrentPointer     // first item
            ELSE Queue[TailPointer].Pointer ← CurrentPointer
         ENDIF
         TailPointer ← CurrentPointer
   ENDIF
ENDPROCEDURE
    • 8Test for no free nodes and report an error
    • 9Store the name in the free node, then move FreePointer on to the next free node (before overwriting the node's pointer)
    • 10Set the new node's pointer to 0
    • 11Link the old tail to the new node (or set HeadPointer if the queue was empty), then update TailPointer
    Paper 4 adviceDo the first-item case separately: with an empty queue there is no old tail to link from. Update FreePointer before you change the pointer field, or you lose the rest of the free list. Pointer diagrams score on the three header pointers as much as on the nodes, so label them all.
    Paper 3 · 9618/32 Oct/Nov 2022, Q11 10 marks Complete, Explain

    A simplified linked list stores flower names in alphabetical order using two 1D arrays: Flower (the names) and NextPointer. HeadPointer is the index of the first name, and 0 marks the end of the list. Initially HeadPointer = 6.

    IndexFlowerNextPointer
    1Rose7
    2Marigold1
    3Foxglove10
    4Iris9
    5Daisy3
    6Dahlia5
    7Saxifrage0
    8Lupin2
    9Lily8
    10Hydrangea4

    (a) Marigold, Dahlia, Saxifrage and Hydrangea are deleted. Show the new HeadPointer and NextPointer values that keep the remaining names in alphabetical order. [3]

    (b) Complete the pseudocode to input a flower name, search the list in order, and output whether it is found. The search ends when the pointer is 0. [5]

    (c) Explain how you could improve the simplified linked list structure. [2]

    ReminderIn (a), follow the order Daisy, Foxglove, Iris, Lily, Lupin, Rose, and make each pointer hold the index of the next name. Deleted rows are left blank.

    (a) HeadPointer 5. Rose 0, Foxglove 4, Iris 9, Daisy 3, Lupin 1, Lily 8.

    • 1(a) Correct HeadPointer (5, Daisy)
    • 2(a) Any three correct NextPointer
    • 3(a) All six NextPointer correct
    Pointer ← HeadPointer
Found ← 0

INPUT FlowerName
WHILE Pointer <> 0
   IF Flower[Pointer] = FlowerName THEN
      Found ← Pointer
      Pointer ← 0
   ELSE

   ENDIF
ENDWHILE

ELSE

    Examiner reportVery few candidates got full marks in (b). Typical errors: a wrong WHILE condition, a wrong assignment for the next value of Pointer, missing THEN, or outputting Flower[Found] when the name is not found (it is not in the array).     Advice: this is the textbook's heap idea in an exam. A free list pointer is the heapStartPointer from the linked list tab. If an improvement is asked for on a linked list, think about the unused nodes.

    Paper 3 · 9618/31 May/June 2023, Q11 11 marks Write, Complete, Explain

    A queue ADT of strings is implemented with: FrontPointer (INTEGER, start of the queue), RearPointer (INTEGER, end of the queue), Length (INTEGER, current size) and Queue (a 1D STRING array). A constant MaxSize limits the queue to 60 items.

    (a) Write the pseudocode to declare MaxSize, FrontPointer, RearPointer, Length and Queue. [3]

    (b) Complete the function Dequeue so it removes the front item (the function stores the item, moves the front pointer, reduces the length, and wraps the pointer round when it passes MaxSize). [4]

    (c) Explain how a new element can be added to the queue if it is implemented using two stacks. [4]

    Reminder(c) is a direct example of implementing one ADT from another: a queue built from two stacks. Two LIFO stacks back to back reverse the order twice, which gives FIFO.
    CONSTANT MaxSize = 60
DECLARE Queue : ARRAY[1:60] OF STRING
DECLARE FrontPointer : INTEGER
DECLARE RearPointer : INTEGER
DECLARE Length : INTEGER
    • 1(a) Correctly defined constant
    • 2(a) Correctly defined array (1:60, 0:59, or using MaxSize)
    • 3(a) Three correctly defined integers
    FUNCTION Dequeue RETURNS STRING
   DECLARE Item : STRING
   IF Length > 0 THEN
      Item ← Queue[FrontPointer]
      FrontPointer ← FrontPointer + 1
      Length ← Length - 1
      IF Length = 0 THEN
         CALL Initialise            // reset the pointers
      ELSE
         IF FrontPointer > MaxSize THEN
            FrontPointer ← 1
         ENDIF
      ENDIF
   ELSE
      OUTPUT "The print queue was empty - error"
      Item ← ""
   ENDIF
   RETURN Item
ENDFUNCTION
    • 4(b) One mark for each correctly completed line (max 4)
    • 5(c) Two stacks are needed so the second can reverse the order of the first
    • 6(c) Stack 1 acts as the queue with the newest elements at the bottom; stack 2 is empty
    • 7(c) To add: pop all elements from stack 1 and push them onto stack 2, push the new element, then pop everything from stack 2 back onto stack 1
    Examiner reportMost candidates got at least one mark for the three integers, but few declared all parts. Part (b) was awarded as 4 marks to every candidate because of a wording problem in the printed question, so do not treat that part as a guide to difficulty. In (c), candidates generally understood that items must leave in the order they entered, which needs data moved between the two stacks.

    Advice: in (c), say what each stack does and in what order you move items. "Use two stacks to make a queue" earns nothing without the reversal.

    Paper 4 · 9618/41 May/June 2026, Q1(a), (b), (c)(i) 15 marks Write program code

    A program stores integer data in a linear queue. The queue is a global 1D array with space for 10 elements. A global head pointer, initialised to -1, points to the first element. A global tail pointer, initialised to -1, points to the last element.

    (a) Write program code to declare the global variables and initialise the queue and pointers. [3]

    (b) Write the function Enqueue(). It takes an integer parameter, returns Boolean FALSE if the queue is full, and otherwise stores the parameter, updates the appropriate pointer(s) and returns TRUE. [7]

    (c)(i) Extend the main program to take 11 integers as input, insert each using the function, output a message whenever the queue is full, and output the final content of the array. Do not dequeue. [5]

    ReminderPaper 4 is marked on working code that you save and screenshot. Write it in your exam language. Python is shown below.
    Queue = []
HeadPointer = -1
TailPointer = -1
for x in range(10):
    Queue.append(-1)

def Enqueue(Data):
    global Queue, TailPointer, HeadPointer
    if TailPointer < 9:
        TailPointer = TailPointer + 1
        Queue[TailPointer] = Data
        if HeadPointer == -1:
            HeadPointer = 0
        return True
    else:
        return False

for x in range(11):
    Returned = Enqueue(int(input("Enter a number ")))
    if not Returned:
        print("Queue full")
print(Queue)
    • 1(a) Global array of 10 integers
    • 2(a) Head and tail pointers both initialised to -1
    • 3(a) Queue values initialised to -1
    • 4(b) Header taking one integer parameter, with the full check returning False
    • 5(b) Otherwise store the parameter at tail pointer + 1
    • 6(b) Increment the tail pointer and return True
    • 7(b) Deal with the first element and set the head pointer to 0
    • 8(c)(i) Take 11 integers as input, call Enqueue() with each, store or check the return value, output a message on False, output the array
    Paper 4 adviceQueue full means the tail pointer is at the last index (9 for 10 elements). Set the head pointer only when the first value goes in. The 11th value must produce the message, so test with 11 inputs and keep the screenshot as evidence. No examiner report is available for this session.
    Real world

    Where these structures show up

    Browser back button

    A stack of visited pages. Back pops the most recent one.

    In an exam: use it to justify why a stack (LIFO) suits the task.

    Print queue

    Jobs are added at the rear and printed from the front, in arrival order.

    In an exam: name front and rear pointers and FIFO.

    Phone contacts or a Python dict

    Look up a number from a name. Names are unique keys, numbers are values.

    In an exam: link it to key, value and "each key once".

    Music playlist

    Songs joined one after the next, easy to insert in the middle without shifting the rest.

    In an exam: advantage of a linked list: insert and delete by changing pointers.

    File system

    Folders branch into folders and files, like a tree of nodes with pointers.

    In an exam: use it as a tree example, with root and child nodes.

    Undo in an editor

    Each action is pushed on a stack. Undo pops the latest one.

    In an exam: tie push and pop to the stack's top pointer.
    Top tips

    What to remember in the exam

    Name the partsSay which type it is built from (array, linked list), then name the pointers. "Array plus a top pointer" earns more than "an array".
    Keep the two pointers apartFor a linked list, startPointer is the list in use and heapStartPointer is the free nodes.
    Null is -1Loops walk the list until the pointer is -1, never until the end of the array.
    Dictionary, in one lineKeys in a linked list, values in a parallel array at the same index, each key stored once.
    Common slipDeclaring the dictionary type with a mix of two structures in one line. Write the TYPE with separate DECLARE lines for keys and values.
    Command words"Show how" and "describe how" need working and detail. "State" needs only the name.
