Sorting: Bubble Sort and Insertion Sort

Two ways to put a list in order. Bubble sort swaps neighbours that are the wrong way round. Insertion sort builds a sorted section one item at a time. Step through both, race them on different lists, and practise the traces and explanations that earn marks.

The big idea

A sorting algorithm rearranges data into order, for example smallest to largest. Sorting makes data easier to read, and it makes faster searching possible (binary search, 19.1.1). Both algorithms here are simple, work in place on an array, and take a quadratic number of steps in the worst case.

Bubble sort

Go through the list comparing each pair of neighbours. If they are in the wrong order, swap them. After one pass the largest unsorted item has "bubbled" to the end. Repeat until a whole pass makes no swaps.

  • Needs a temporary variable to swap.
  • A Swapped flag lets it stop early.
  • After pass k, the last k items are in their final place.

Insertion sort

Treat the start of the list as already sorted. Take the next item (the key), shift every larger sorted item one place right, and drop the key into the gap.

  • The sorted section grows from the left.
  • Very quick on nearly sorted data.
  • Items before the key are in order but not final yet.

Both are O(n²) because there is a loop inside a loop: for n items, roughly n passes of up to n comparisons. Doubling the list size roughly quadruples the work (see 19.1.5).

worst-case comparisons = (n − 1) + (n − 2) + … + 1 = n(n − 1) / 2

Swapping needs a temporary variable

Writing Data[i] ← Data[i + 1] on its own destroys the old value of Data[i]. Save it first.

Temp ← Data[i]
Data[i] ← Data[i + 1]
Data[i + 1] ← Temp

Python can swap in one line, a[i], a[i+1] = a[i+1], a[i], but pseudocode answers need the three-line version.

5 · Multiple choice

Descriptions are kept general. Use them as examples of ideas, not as exact descriptions of any company's software.

Sorting a hand of playing cards

Most people pick up each new card and slide it into the right place among the cards they already hold. That is an insertion sort.

Exam use: a quick way to explain the key, the sorted section and the shifting.

A leaderboard that is almost always in order

When one player's score changes, only that player moves a few places. A sort that works well on nearly sorted data finishes in very few steps.

Exam use: why insertion sort (or bubble sort with a Swapped flag) can be better than expected on nearly sorted data.

Sorting before searching

A shop sorts its product codes once so that every lookup afterwards can use a binary search.

Exam use: link 19.1.2 to 19.1.1: the cost of sorting is paid once, then repaid by many fast searches.

Spreadsheet column sort

Clicking a column header to sort rows is a sorting algorithm on a large data set. Real software uses faster algorithms than bubble or insertion sort for big lists, though many of them use insertion sort for short sections.

Exam use: shows that simple sorts matter even when the main algorithm is cleverer, and that quadratic sorts are poor for very large lists.

Re-shelving library books

If books are put back in the wrong order, a librarian fixes them by checking neighbours and swapping those that are the wrong way round.

Exam use: a real picture of swapping adjacent items, as in a bubble sort.

Tiny lists in embedded devices

A small device sorting five sensor readings does not need a complicated algorithm. A few lines of bubble sort use almost no extra memory.

Exam use: a justification for choosing a simple algorithm: short code, in place, fast enough for small n.

Exam-style questions

Open each question for reminders, a model answer and common mistakes. Each coloured phrase earns one mark; the number shows which mark point it is.

Q1 Describe 4 marks Describe how a bubble sort puts an array of numbers into ascending order.
ReminderCompare adjacent items, swap, pass through the list, repeat until no swaps.
Each item is compared with the next item in the array (adjacent pairs). If the two items are in the wrong order (the first is larger), they are swapped. This is repeated from the start to the end of the array (one pass), which moves the largest unsorted value to the end. Further passes are made until a complete pass is made with no swaps, so the array is sorted.
Common mistakeSaying "it finds the smallest and moves it to the front". That describes a different sort.
Q2 Complete 4 marks A bubble sort is applied to [8, 3, 5, 1] (ascending). Show the array at the end of each pass until the sort ends.
ReminderA pass compares every remaining pair once. Keep going until a pass makes no swaps; that pass counts.
PassArray at end of passSwaps
13, 5, 1, 83
23, 1, 5, 81
31, 3, 5, 81
41, 3, 5, 8 (no swaps, so the sort stops)0
Common mistakeStopping at pass 3. The algorithm only knows the array is sorted when a pass makes no swaps.
Q3 Describe 4 marks Describe how an insertion sort puts an array into ascending order.
ReminderThe sorted section on the left, the key, shifting, and insertion.
The first item is treated as a sorted section. The next unsorted item is taken as the key. The key is compared with the items in the sorted section, working from right to left. Every item larger than the key is shifted one place to the right. The key is placed in the gap, and this repeats for each remaining item until the whole array is sorted.
Common mistakeDescribing swaps of adjacent items. Insertion sort shifts items and places the key once.
Q4 Complete 3 marks Complete the missing lines of this bubble sort for the array Data with N items (indexes 0 to N - 1). 
REPEAT
   Swapped ← FALSE
   FOR i ← 0 TO N - 2
      IF ........(A)........ THEN
         Temp ← Data[i]
         ........(B)........
         Data[i + 1] ← Temp
         ........(C)........
      ENDIF
   NEXT i
UNTIL Swapped = FALSE
ReminderThe comparison must test for the wrong order. The swap needs three lines. The flag records that a swap happened.
(A) Data[i] > Data[i + 1]
(B) Data[i] ← Data[i + 1]
(C) Swapped ← TRUE
Common mistakeSetting Swapped ← FALSE inside the IF. The flag is cleared at the start of each pass, and set TRUE when a swap happens.
Q5 Explain 3 marks Explain the purpose of the Swapped flag in a bubble sort.
ReminderWhat it records, what happens when it stays FALSE, and the benefit.
The flag records whether any swap was made during a pass. If it is still FALSE at the end of a pass, no items were out of order, so the array is sorted and the algorithm can stop. This avoids unnecessary extra passes, so an already or nearly sorted array is finished much sooner.
Common mistakeWriting that the flag "tells you which items to swap". It tells you whether any swaps happened.
Q6 Compare 4 marks An array of 5,000 scores is already almost in order, with only a few values out of place. Compare how well bubble sort (with a Swapped flag) and insertion sort will suit this data.
ReminderUse the data in the scenario. Talk about how many comparisons and swaps or shifts are needed.
Insertion sort only needs to move the few items that are out of place; most keys are already larger than the item to their left, so there is one comparison and no shift for each. That is close to its best case of about n − 1 comparisons. Bubble sort with a Swapped flag also benefits, because few swaps are needed and it stops after a pass with no swaps. However it may still need several passes, each comparing almost all of the 5,000 items, while a small value near the end moves only one place per pass; insertion sort is likely to be quicker.
Common mistakeSaying both are "O(n²) so the same". The scenario asks about nearly sorted data, where both can do much better than their worst case.
Q7 Calculate 3 marks A bubble sort without a Swapped flag always makes every comparison in every pass, shortening each pass by one. Calculate the number of comparisons needed to sort 50 items.
ReminderPass 1 has 49 comparisons, pass 2 has 48, and so on down to 1. Use n(n − 1) / 2.
Comparisons = 49 + 48 + … + 1 = n(n − 1) / 2 = 50 × 49 / 2 = 1,225 comparisons.
Common mistakeUsing n² = 2,500 or n × (n − 1) = 2,450 and forgetting to halve.
Q8 Discuss 4 marks A program holds an unsorted array of 10,000 records and must look up just three of them. A programmer suggests sorting the array first with a bubble sort, then using a binary search for each lookup. Discuss whether this is sensible.
ReminderCost of sorting compared with the saving on searching. Use the numbers.
A bubble sort of 10,000 items could need around 50 million comparisons (n(n − 1) / 2). A linear search of 10,000 items needs at most 10,000 comparisons, so three searches need at most 30,000. Binary search would save time on each lookup (at most 14 comparisons), but with only three lookups the saving is tiny compared with the sorting cost. So sorting first is not sensible here; a linear search on the unsorted data is better. Sorting would only pay off with a very large number of searches.
Common mistakeSaying "binary search is always faster" without counting the cost of sorting the data first.

Top tips

  • Know what a pass is. In bubble sort, one pass compares every remaining adjacent pair once. After pass k, the last k items are final.
  • The last pass has no swaps. A bubble sort trace is not finished until you show a pass where nothing swapped.
  • Insertion sort shifts, bubble sort swaps. Do not mix the descriptions up.
  • Swapping needs Temp. Three lines in pseudocode. Without it, a value is lost.
  • Quote the formula. Worst case n(n − 1) / 2 comparisons for both. Show the substitution.
  • Say "nearly sorted". Both sorts (bubble with a flag) approach n − 1 comparisons on nearly sorted data.
  • Both are O(n²) in the worst case. Doubling the size roughly quadruples the work.
  • Link to searching. Sorting is a cost paid once; binary search repays it only if you search many times.
  • Check array bounds. This artifact uses index 0. Many CIE questions use 1.
