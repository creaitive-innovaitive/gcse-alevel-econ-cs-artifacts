Two's Complement: Every Question Type

What the wording means, which method to use, and a model answer for each kind of question. Two's complement is how a computer stores negative whole numbers in binary.

The one idea you need

In ordinary 8-bit binary the place values are 128, 64, 32, 16, 8, 4, 2, 1. In two's complement only one thing changes: the leftmost place value becomes −128.

−1286432168421
11010011

−128 + 64 + 16 + 2 + 1 = −45

That leftmost bit is the sign bit. 0 means the number is zero or positive. 1 means it is negative.

The three methods

Method A: place values

Use it to read a two's complement number.

Write −128 64 32 16 8 4 2 1 above the bits. Add the values that have a 1 beneath. Remember the −128.

11110000 → −128 + 64 + 32 + 16 = −16

Method B: flip and add 1

Use it to make a negative number.

1. Write the positive number in 8-bit binary. 2. Flip every bit. 3. Add 1.

−20: 00010100 → 11101011 → 11101100

Method B works backwards too

To read a negative number another way: flip, add 1, and you get the positive size. Put a minus in front.

11101100 → 00010011 → 00010100 = 20 → −20

Fast method (optional)

Starting from the right, copy every bit up to and including the first 1. Flip all the bits after that.

00010100: copy 100, flip 00010 → 11101100

Special case10000000 is −128. Flipping and adding 1 gives 10000000 again, because +128 does not fit in 8 bits. Just read it with Method A.

The range

With n bits the range is −2ⁿ⁻¹ to +(2ⁿ⁻¹ − 1). There is one more negative value than positive, because 0 uses up one of the positive-side patterns.

Why computers use it

  • It stores negative numbers using only 1s and 0s.
  • Subtraction becomes addition. A − B is calculated as A + (−B), so the processor needs no separate subtraction circuit.
  • There is only one zero. (00000000. No separate "negative zero".)

Spelling: it is complement (completes the number), not compliment.

The question types, with model answers

Open each one. Underlined phrases are mark points; the number shows which mark.

Type 1 Represent 3 marks Write −45 as an 8-bit two's complement binary number.
How to answerPositive version first, then flip, then add 1. Always 8 bits. Show each stage: the marks are for the stages.
45 = 00101101 Flip the bits: 11010010 Add 1: 11010011
Common mistakesFlipping but forgetting +1 (gives −46). Starting from the wrong number (flipping 45 as 101101 without the leading zeros). Putting a 1 in front of 00101101 and calling it done.
Type 2 State 2 marks State the denary value of the 8-bit two's complement number 11010011.
How to answerLeading 1, so it is negative. Method A: add the place values, with the left one as −128. Check the sign makes sense.
−128 + 64 + 16 + 2 + 1 = −45

Check with Method B: flip 11010011 → 00101100, add 1 → 00101101 = 45, so the number is −45. ✓

Common mistakesUsing +128 for the left bit (gives 211). Dropping the minus sign. Adding the 0 columns.
Type 3 State 1 mark State the denary value of the 8-bit two's complement number 01001101.
How to answerLeading 0, so it is positive. It is the same as ordinary binary. No flipping needed.
64 + 8 + 4 + 1 = 77
Common mistakeFlipping and adding 1 anyway. If the left bit is 0, nothing special happens.
Type 4 Give 2 marks Give the smallest and largest denary numbers that can be stored as an 8-bit two's complement number.
How to answerSmallest: 1 followed by all 0s. Largest: 0 followed by all 1s. Learn the pair −128 and 127.
Smallest: 10000000 = −128 Largest: 01111111 = +127

Other bit lengths: n bits gives −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1. For 4 bits that is −8 to 7. The number of different values is always 2ⁿ (256 for 8 bits).

Common mistakeWriting −127 to 128, or −128 to 128. The positive side stops one short.
Type 5 Show 4 marks Calculate 30 − 12 using 8-bit two's complement. Show your working.
How to answerSubtraction is turned into addition: 30 − 12 = 30 + (−12). Make −12, add, throw away any ninth bit.
30 = 00011110, 12 = 00001100 −12: flip 00001100 → 11110011, add 1 → 11110100 00011110 + 11110100 = 1 00010010 The carry out of the 8th bit is discarded, giving 00010010 = 18
Common mistakesSubtracting the binary numbers column by column. Calling the discarded ninth bit "overflow". Here it is expected and the answer is correct. Check by converting back: 00010010 = 18 ✓
Type 6 Explain 2 marks Explain why the binary number 11111111 is smaller than 00000001 when stored in two's complement.
How to answerGive both values, and name the sign bit.
The leftmost bit is the sign bit. In 11111111 it is 1, so the number is negative (−128 + 127 = −1). 00000001 has a 0 sign bit, so it is positive (+1), and any negative number is smaller than a positive one.
Common mistakeReading both as ordinary binary (255 and 1), which makes 11111111 the bigger.
Type 7 Give 2 marks Give two reasons why computers use two's complement to store negative numbers.
How to answerTwo separate points. Pick from: negatives, subtraction by addition, one zero.
It allows negative numbers to be stored using only binary digits. Subtraction can be done by adding a negative number, so the processor can use the same addition circuit and needs no separate subtraction circuit.

Another valid point: there is only one representation of zero.

Type 8 (extension) Describe 2 marks 01100100 + 00110010 is calculated in 8-bit two's complement. Describe the result.
How to answerAdd, then look at the sign bit. Two positives cannot make a negative.
The sum is 10010110, which has a 1 as the sign bit, so it reads as −106. 100 + 50 = 150 is bigger than 127, so the answer does not fit in 8 bits: overflow has occurred and the stored result is wrong.

Rule of thumb: if two numbers with the same sign give a result with the opposite sign, there has been overflow.

Descriptions are kept general.

Signed integers in programming

An 8-bit signed integer type (such as int8 in C-style languages) holds −128 to 127. A 16-bit one holds −32,768 to 32,767, and a 32-bit one about ±2.1 billion. These are all two's complement.

Exam use: a ready example of a range question: n bits gives −2ⁿ⁻¹ to 2ⁿ⁻¹ − 1.

Digital audio

CD-quality sound is stored as 16-bit samples. The wave goes above and below zero, so each sample is a signed number from −32,768 to 32,767.

Exam use: links to 1.2 sound sampling, and shows why a negative value is needed.

Temperature sensors

A weather station storing the temperature in one byte needs to record −20 °C as well as 35 °C, so it uses two's complement.

Exam use: a context for "why do we need negative numbers in binary?"

Counters that wrap round

When a signed counter passes its largest value it wraps to a large negative one. YouTube's view counter hit this limit in 2014, at 2,147,483,647 views, and moved to a 64-bit counter.

Exam use: shows overflow in two's complement: two positives cannot give a negative.

Top tips

  • Decide the job first. Making a number (Method B) or reading one (Method A)?
  • Check the left bit. 0 means nothing special. 1 means negative.
  • The left place value is −128, not +128.
  • Write all 8 bits including leading zeros. Pad before flipping.
  • Flip, then add 1. Both steps, in that order. Show each line for method marks.
  • Subtraction is addition. A − B = A + (−B). Discard a ninth bit.
  • Check your answer backwards. Read your binary with Method A and see if you get your starting number.
  • Range: −128 to 127, 256 values. The positive side is one short.
