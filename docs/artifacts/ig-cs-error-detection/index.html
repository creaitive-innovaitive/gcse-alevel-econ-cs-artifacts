Methods of Error Detection

Why data can be corrupted in transmission, and how parity checks, checksums, echo checks, check digits and automatic repeat requests find the errors.

The big idea

When data is transmitted it can be corrupted, lost or even gained. The receiver cannot see the original, so the sender and receiver agree a check. The sender adds something extra (a parity bit, a checksum, a check digit) or the receiver replies (echo, acknowledgement). If the check does not work out, the data is flagged as wrong and usually re-sent.

2.2.1 Why errors happen

  • Interference: every type of cable can suffer electrical interference, which can corrupt or lose data.
  • Packet switching problems: packets can be lost, or data can even be gained.
  • Skew: in parallel transmission, bits arriving out of step can corrupt the data.

Corrupted data matters because a computer cannot guess what was meant. A person can read "Can you raed tihs?", but a computer would not recognise the word.

The methods below detect errors after transmission. Most then ask for the data to be sent again.

2.2.2 Parity checks

A parity check uses the number of 1-bits in a byte. Sender and receiver agree beforehand whether they use even parity (an even number of 1-bits) or odd parity (an odd number of 1-bits).

One bit of the byte, usually the most significant (left-most) bit, is reserved as the parity bit. It is set to 0 or 1 so that the whole byte has the agreed parity.

Worked example: 7 data bits 1101100

Parity1-bits in the dataParity bitByte sent
Even4 (even already)00 1101100
Odd4 (needs one more)11 1101100

The receiver recounts the 1-bits. If the byte no longer has the agreed parity, an error is flagged.

Two weaknesses1. If two bits change, the count of 1-bits can still have the right parity, so the error is missed. 2. Even when an error is flagged, you cannot tell which bit changed.

Parity blocks: finding the bad bit

To locate an error, a block of bytes is checked in both directions. Each byte has its own parity bit (the row check), and an extra byte, the parity byte, is sent at the end of the block, made of the parity bits for each column (the vertical check). It also marks the end of the block.

If one bit flips, one row and one column now have the wrong parity. The bad bit is where they cross. It can be corrected automatically, or the block can be sent again.

Checksum

Data is sent in blocks, with an extra value, the checksum, sent at the end.

  1. The sender calculates the checksum from the block using an agreed algorithm.
  2. The checksum is sent with the block.
  3. The receiver recalculates the checksum from the block it received.
  4. Same: no error. Different: a request is made to re-send the block.

Echo check

The receiver sends a copy of the data back to the sender, who compares it with the original. If they are the same, the data was sent correctly. If they differ, there was an error.

Weakness: if the two copies differ, you cannot tell whether the error happened on the way there or on the way back. It is not very reliable.

2.2.3 Check digits

A check digit is the final digit of a code, calculated from all the other digits. It is used on barcodes, ISBNs and vehicle identification numbers (VINs). It is a data entry check, not a transmission check. It finds mistakes made by typing a number in or scanning a barcode wrongly.

Errors a check digit can usually detect

  • Incorrect digit: 5327 instead of 5307
  • Transposition (two digits swapped): 5037 instead of 5307
  • Omitted or extra digit: 537 or 53107 instead of 5307
  • Phonetic error: 13 (thirteen) instead of 30 (thirty)

Remember

The check digit is calculated when the code is created, and re-calculated every time the code is entered. A mismatch means the number was mistyped or mis-scanned.

The exam gives you the steps of the algorithm. You need to be able to follow them, not remember them.

ISBN-13: generate the check digit from 12 digits

  1. Add the digits in odd positions (1st, 3rd, 5th … 11th).
  2. Add the digits in even positions (2nd … 12th) and multiply by 3.
  3. Add the two results and divide by 10.
  4. Take the remainder. If it is 0, the check digit is 0. Otherwise the check digit is 10 − remainder.

Example: 9 7 8 0 3 4 0 9 8 3 8 2. Odd: 9+8+3+0+8+8 = 36. Even: 3 × (7+0+4+9+3+2) = 75. 36 + 75 = 111; 111 ÷ 10 leaves remainder 1; check digit = 10 − 1 = 9.

Verify the full 13 digits: do the same, but include the check digit in the odd-position sum. The number is correct if the remainder is 0. (Example: 45 + 75 = 120, remainder 0 ✓.)

Modulo-11: generate the check digit from 7 digits

  1. Give each digit a weighting from the left: 8, 7, 6, 5, 4, 3, 2.
  2. Multiply each digit by its weighting and add the results.
  3. Divide the total by 11.
  4. Subtract the remainder from 11 to get the check digit (10 is written as X).

Example: 4 1 5 6 7 1 0. 32 + 7 + 30 + 30 + 28 + 3 + 0 = 130. 130 ÷ 11 = 11 remainder 9. 11 − 9 = 2. The number is 4 1 5 6 7 1 0 2.

Verify the 8 digits with weightings 8, 7, 6, 5, 4, 3, 2, 1 (the check digit has weighting 1). Total 132 ÷ 11 = 12 remainder 0, so the number is correct.

2.2.4 Automatic repeat request (ARQ)

ARQ uses acknowledgements and a timeout.

  1. The data arrives with an error-detection code, typically a CRC.
  2. No error found: the receiver sends a positive acknowledgement back to the sender.
  3. Error found: the receiver sends a negative acknowledgement and asks for the data to be re-sent.
  4. The sender waits a set time, the timeout. If no acknowledgement of either kind arrives in that time, it automatically re-sends the data.
  5. This repeats until a positive acknowledgement arrives, or a set number of re-transmissions has been reached.

ARQ is often used by mobile phone networks to make sure data arrives intact.

Barcodes and ISBNs

Every book carries a 13-digit ISBN whose last digit is a check digit. Scan it at a till and the system re-calculates the check digit. A mis-scan will not match, so the till asks you to scan again rather than selling you the wrong item.

Exam use: the standard example of a check digit. Say it detects data entry errors, such as a mis-scanned barcode.

Mobile phone networks

Radio signals suffer interference, so phone networks use automatic repeat requests. If a block of data arrives damaged, a negative acknowledgement is sent and the block is repeated.

Exam use: a real example of ARQ. Describe acknowledgements, timeout and re-sending.

Memory and storage

Data stored in memory or on disks can be checked with parity bits and checksums too. A checksum for a downloaded file lets you check that the copy on your computer matches the original.

Exam use: shows a checksum is worked out from a whole block of data, then compared.

Vehicle identification numbers

A car's VIN includes a check digit, so a mistyped VIN on a registration form or in a parts database can be flagged immediately.

Exam use: a second example of where check digits are used.

"Repeat that, please?"

On a poor phone line you might say "Did you say fifty or fifteen?" and the other person repeats it. That is the idea behind an echo check: send it back so it can be compared.

Exam use: an analogy for echo check, and for why it is not very reliable if the two versions differ.

Exam-style questions

Open each question for reminders, a model answer and common mistakes. Each underlined phrase earns one mark; the number shows which mark point it is.

Q1 Give 2 marks Give two ways in which data can become corrupted during transmission.
ReminderChoose two from interference, packet switching problems and skew.
Interference (electrical) on the cable can change or lose bits. Skew in parallel transmission, where bits arrive out of step; (or) problems during packet switching, such as packets being lost.
Common mistakeAnswering with the checking method. The question asks for the cause of the errors.
Q2 Calculate 2 marks (a) Even parity is used. The 7 data bits are 1011011. What is the parity bit? (b) Odd parity is used. The 7 data bits are 1100110. What is the parity bit?
ReminderCount the 1-bits first. Then decide whether the parity bit must be 0 or 1 to make the total match the parity.
(a) 1011011 has five 1-bits (odd), so the parity bit is 1, to make six. (b) 1100110 has four 1-bits (even), so the parity bit is 1, to make five (odd).
Common mistakeUsing the wrong parity for the part. Underline "even" or "odd" in the question first.
Q3 Explain 2 marks Even parity is used. The byte 01101101 is received. Has an error been detected?
ReminderCount the 1-bits in what was received, compare with the agreed parity.
The byte contains five 1-bits, which is an odd number. Even parity was agreed, so an error has been detected.
Common mistakeCounting 0-bits. Parity is about the number of 1-bits.
Q4 Explain 2 marks Explain why a parity check might not detect an error in a transmitted byte.
ReminderIt is about two bits changing.
If two bits change (for example, one 1 becomes 0 and one 0 becomes 1, or two bits flip in the same direction), the byte is corrupted. But the number of 1-bits still has the same parity, so the receiver sees no error.
Common mistake"Parity is unreliable". Say why: the count still looks right.
Q5 Describe 4 marks Describe how a checksum is used to check for errors in a block of data.
ReminderCalculate, send with the block, recalculate, compare. Mention the agreed algorithm.
The sender calculates the checksum from the block of data, using an agreed algorithm. The checksum is sent with (after) the block of data. The receiver recalculates the checksum from the block it received, using the same algorithm, and compares it with the one sent. If they match there is no error; if they differ, the receiver asks for the block to be re-sent.
Common mistakeForgetting the receiver calculates its own. Without that, there is nothing to compare.
Q6 Describe 3 marks Describe how an echo check works, and give one weakness.
ReminderSend, return, compare. Then the weakness.
The data is sent to the receiver, who sends a copy of it back to the sender. The sender compares the returned data with the original; if they are different, an error has occurred. Weakness: if they differ, the sender cannot tell whether the error happened on the way to the receiver or on the way back.
Common mistakeSaying the receiver compares the data. It is the sender who compares.
Q7 Describe 4 marks Describe how an automatic repeat request (ARQ) is used to check for errors in data transmission.
ReminderError check, positive and negative acknowledgement, timeout, re-send.
The receiver checks the data using an error-detection code (such as a CRC) that was sent with it. If no error is found, a positive acknowledgement is sent back to the sender; if an error is found, a negative acknowledgement is sent and the data is re-sent. The sender waits for a set time (the timeout); if no acknowledgement arrives in that time, it automatically re-sends the data. This repeats until a positive acknowledgement is received, or a set number of re-transmissions has been made.
Common mistakeForgetting the timeout, which covers the case where no reply arrives at all.
Q8 Describe 3 marks A block of bytes is sent using even parity in both directions, with a parity byte at the end. It arrives as shown. Find the error and give the correct value of the byte affected.

ReminderCheck every row, then every column. The wrong row and wrong column cross at the error.
Byte 3 has five 1-bits (odd), so its row has the wrong parity. Column 6 has three 1-bits in the data bytes plus the parity byte (odd), so its column has the wrong parity; the error is the bit where they cross: byte 3, bit 6. That bit should be 0, so byte 3 should be 11110000.

Q9 Describe 3 marks Describe three differences between a checksum and a check digit.
ReminderThink purpose, size/position, and when it is used.
A checksum checks data after transmission; a check digit checks data entry (typing or scanning). A checksum is calculated from a whole block of data; a check digit is calculated from the other digits of one number or code. A checksum is a value sent after the block of data; a check digit is a single digit at the end of a code (such as an ISBN).
Common mistakeSaying "they both check for errors". The question asks for differences.
Q10 Calculate 4 marks The ISBN-13 check digit is found like this: add the digits in odd positions; add the digits in even positions and multiply by 3; add the two results and find the remainder when divided by 10; if the remainder is 0 the check digit is 0, otherwise subtract it from 10. Find the check digit for 978030640615.
ReminderShow each stage. Method marks are available even if the last step slips.
Odd positions: 9 + 8 + 3 + 6 + 0 + 1 = 27 Even positions: 3 × (7 + 0 + 0 + 4 + 6 + 5) = 3 × 22 = 66 27 + 66 = 93; 93 ÷ 10 leaves a remainder of 3 Check digit = 10 − 3 = 7

Q11 Describe 3 marks A check digit can detect certain errors when a number is typed in. Describe three types of error it can detect.
ReminderGive a short example with each type.
An incorrect digit, for example 5327 typed instead of 5307. A transposition error, where two digits swap places, for example 5037 instead of 5307. An omitted or extra digit, for example 537 or 53107 instead of 5307. (Also acceptable: a phonetic error, 13 for 30.)
Common mistakeListing errors the check digit cannot help with, such as "the wrong product was chosen".

Top tips

  • Count the 1-bits for parity, never the 0-bits. Underline "even" or "odd" in the question.
  • The parity bit goes in the left-most (most significant) position unless the question says otherwise.
  • Parity does not find which bit. A parity block does, using the row and the column.
  • Parity can miss errors when an even number of bits change.
  • Checksum: two calculations. Sender and receiver both calculate, then compare.
  • Echo check: the sender compares. Weakness: cannot tell which journey had the error.
  • ARQ needs a timeout as well as the positive and negative acknowledgements.
  • Check digit = data entry. Checksum, parity and echo = transmission.
  • Show every step in check digit calculations. You can earn method marks.
