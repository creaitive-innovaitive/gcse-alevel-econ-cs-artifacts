Why compress, and the two methods

Compression makes a file smaller. Smaller files take up less storage, download faster and use less bandwidth when streamed. There are two families of method.

Lossless

Nothing is thrown away

The data is stored more cleverly. When decompressed, the file is rebuilt exactly as it was. RLE is lossless.

Use when every bit matters: text documents, program files, spreadsheets, medical images.

Lossy

Some data is removed for good

Detail the user is unlikely to notice is deleted. The original can never be recovered, but the file gets much smaller.

Use when a small drop in quality is fine: streamed music, photos on a website, video calls.

Run-length encoding, step by step

A run is a stretch of the same value repeated. RLE replaces each run with two things: how many (the count) and what (the value). AAAAA becomes 5A.

Encoded
Saved
The four things RLE does: keep a count, compare each new item with the current run, write count + value when the run breaks, and write the last run when the data ends. Notice the second A run is a separate token. RLE only joins items that are next to each other.
When RLE backfires. Try ABCDEF. Every run has length 1, so 1A1B1C1D1E1F is twice as long. RLE only helps when there are long runs.

RLE on a bitmap image

An image is a grid of pixels. Here each pixel is 1 bit: black (B) or white (W). Encode one row at a time, left to right. Click or drag on the grid to draw, or pick a preset.

Bits per run = bits needed to store the longest count, plus 1 bit for the colour. Longest run of 8 needs 4 bits for the count (0–15), so each run costs 5 bits.

Sound: sample rate and bit depth

A sound is stored by measuring the wave many times a second (sample rate, in Hz) and rounding each measurement to one of 2bits levels (bit depth). The dashed line is the real sound. The solid line is what gets stored.

Bits
Bytes
File size

File size = sample rate × bit depth × length in seconds (mono). Divide by 8 for bytes and by 1024 for KiB. Lowering the rate or depth is lossy: the sound is less accurate and cannot be restored.

Image: resolution and colour depth

Colours possible
File size

Image size = width × height × colour depth (in bits). Lower resolution and lower colour depth are both lossy.

    Top tips

    Say "data", not just "quality"

    Lossless means no data is lost and the original can be rebuilt. "No loss of quality" alone often earns nothing.

    Count then value

    Write RLE as count first, then the value: 4W3B. Match the format in the question if it shows one.

    Runs only join neighbours

    WWBWW is 2W1B2W, not 4W1B. Separate runs stay separate.

    Check the answer is shorter

    If the encoded version is not smaller, say so. Short runs make RLE useless, and examiners like this point.

    Lossy is permanent

    The removed data cannot be recovered. Always link it to a reason: smaller size, faster streaming, less storage.

    Show the calculation

    Sample rate × bit depth × seconds. Then ÷ 8 for bytes, ÷ 1024 for KiB. Method marks are easy to pick up.

    Two-digit counts

    12A means twelve As, not one then two. Read the whole number before the letter.

    Match your reason to the data

    Text and programs need lossless. Music, photos and video usually allow lossy.

    In each model answer, every coloured highlight is one mark.

    2 marksState what is meant by lossless compression.
    A compression method that reduces the file size without permanently removing any data, so the original file can be rebuilt exactly when decompressed.
    Tip: "State" with 2 marks means two short points. Avoid "no loss of quality" on its own.
    3 marksDescribe how lossy compression can reduce the size of a sound file.
    Some data is permanently removed from the file. For example the sample rate or bit depth is reduced, so fewer or less detailed samples are stored. Sounds that humans are unlikely to hear can be deleted.
    Tip: Three marks, three separate points. Naming sample rate or bit depth turns a vague answer into a full-mark one.
    3 marksA row of pixels is WWWWBBBBBBWW. Show how it is stored using run-length encoding (RLE).
    Runs: WWWW, BBBBBB, WW.
    4W 6B 2W → 4W6B2W
    12 items become 6 characters.
    Tip: One mark per correct run. Keep the format count then value. Do not merge the two W runs.
    4 marksExplain why RLE would not work well on a photograph.
    A photograph contains many different colours, so neighbouring pixels are rarely identical. The runs are very short, often length 1. Each run needs a count and a value, so the encoded file can be the same size or larger than the original.
    Tip: "Explain" is a chain: cause, then effect, then result. Finish on the file size.
    3 marksExplain why a text document should be compressed using lossless compression.
    Lossy compression would remove some of the characters or data, so the text could be changed or unreadable. Lossless means the original document can be recreated exactly.
    Tip: Tie the answer to the data type. Text and programs cannot lose a single character.
    4 marksA streaming service uses lossy compression for its films. Give two benefits and two drawbacks.
    Benefits: the file size is much smaller, so it streams faster with less buffering and uses less bandwidth. Drawbacks: some data is lost permanently, so the picture or sound quality is reduced.
    Tip: Also acceptable: less storage needed on the servers. Make sure you give the number of points asked for, no more.
    3 marksCalculate the file size, in KiB, of a 30 second mono sound recording with a sample rate of 8000 Hz and a bit depth of 16 bits.
    8000 × 16 × 30 = 3 840 000 bits
    ÷ 8 = 480 000 bytes; ÷ 1024 = 468.75 KiB
    Tip: Check your answer with the sound sliders above. Set 8000 Hz, 16 bits, 30 s.
