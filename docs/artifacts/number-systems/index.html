Number Systems

Binary, denary and hexadecimal, how to convert between them, how computers add, shift and store negative numbers, and why it all comes down to on and off.

The big idea

A computer is built from billions of tiny switches (transistors) that are either on or off. Two states means two digits, so all data is stored as binary: 1 for on, 0 for off. Humans prefer denary (base 10) and, for reading long binary values, hexadecimal (base 16).

Three number systems

SystemBaseDigitsPlace values (right to left)
Denary100 to 91, 10, 100, 1000 …
Binary20, 11, 2, 4, 8, 16, 32, 64, 128 …
Hexadecimal160 to 9, then A to F1, 16, 256, 4096 …

In hex, A = 10, B = 11, C = 12, D = 13, E = 14, F = 15.

A bit is one binary digit. A nibble is 4 bits. A byte is 8 bits and holds 0 to 255 (256 values). The leftmost bit has the biggest place value: the most significant bit (MSB). The rightmost is the least significant bit (LSB).

Converting

Binary to denary

Write the place values above the bits and add up the ones with a 1 beneath.

1 0 1 1 0 1 0 1
128 + 32 + 16 + 4 + 1 = 181

Denary to binary

Go from 128 downwards. If the place value fits into what is left, write 1 and subtract it. Otherwise write 0.

181: 128 fits (53 left), 64 no, 32 fits (21), 16 fits (5), 8 no, 4 fits (1), 2 no, 1 fits → 10110101

Binary to hex

Split into nibbles from the right and convert each nibble on its own.

1011 1110 → B and E → BE

Hex to binary

Turn each hex digit into a 4-bit nibble. Keep the leading zeros.

3F → 0011 and 1111 → 00111111

Hex to denary: multiply the left digit by 16 and add the right. 3F = 3 × 16 + 15 = 63. Denary to hex: divide by 16; the quotient is the left digit and the remainder is the right. 203 ÷ 16 = 12 remainder 11 → C and B → CB.

Why use hexadecimal?

  • Shorter. One hex digit replaces four bits, so 8 bits become 2 digits.
  • Easier for humans to read, remember and copy, with fewer transcription errors than a string of 1s and 0s.
  • Converts to binary easily, because 16 is 2⁴: each hex digit is exactly one nibble.
Not the reasonHex does not take less storage. The computer still stores binary. Hex is only a human-friendly way to write it.

Where you will see hex: HTML colour codes (#FF8800), MAC addresses, IPv6 addresses, memory addresses and memory dumps, error codes.

Binary addition

Work from the right, column by column. 0+0 = 0, 0+1 = 1, 1+1 = 10 (write 0, carry 1), 1+1+1 = 11 (write 1, carry 1).

Overflow. A register holds a fixed number of bits. If the sum needs more bits than are available (for 8 bits, anything above 255), the extra carry has nowhere to go. It is lost, the stored answer is wrong, and an overflow error occurs.

Logical shifts

A logical shift moves every bit left or right by a number of places. Empty places fill with 0 and bits shifted off the end are lost.

Left shift by n

Multiplies by 2ⁿ. 00010110 (22) shifted left 2 → 01011000 (88).

If a 1 is pushed off the left end, the answer is wrong.

Right shift by n

Divides by 2ⁿ, dropping any remainder. 00010110 (22) shifted right 2 → 00000101 (5).

If a 1 is pushed off the right end, precision is lost (22 ÷ 4 is 5.5, not 5).

Negative numbers: two's complement

In 8-bit two's complement the leftmost bit has a place value of −128 instead of +128. The other columns are normal. A leading 1 means the number is negative.

−1286432168421Value
11010011−128 + 64 + 16 + 2 + 1 = −45

To make a number negative: write the positive value in binary, flip every bit, add 1. The range of 8-bit two's complement is −128 to +127.

HTML and CSS colour codes

A web page colour such as #1E90FF is three bytes in hex: 1E for red, 90 for green, FF for blue. That is 16.7 million combinations from 24 bits.

Exam use: a ready example for "give a use of hexadecimal". Be ready to convert each pair to binary.

MAC and IPv6 addresses

A MAC address identifies a network card and is written as six pairs of hex digits, such as 3C:22:FB:1A:09:D4. IPv6 addresses are written in hex groups for the same reason: they are 128 bits long, which would be unreadable in binary.

Exam use: shows that hex makes long binary values shorter and easier to read and copy without mistakes.

Memory dumps and error codes

When a program crashes, debugging tools show memory addresses and contents in hex. Windows "blue screen" stop codes are hex too (for example 0x0000007B).

Exam use: programmers need to read raw memory, and hex maps neatly onto bytes.

Ariane 5, 1996

The first Ariane 5 rocket veered off course and was destroyed after about 37 seconds. A speed-related value held as a 64-bit floating-point number was converted into a 16-bit signed integer. It was too big, the conversion overflowed, and the guidance computer shut down.

Exam use: a famous consequence of overflow: the value needs more bits than are available.

Boeing 787 and the 248-day counter

In 2015 aviation regulators warned that a Boeing 787 power-control unit could shut down if it ran for 248 days without a restart. A 32-bit counter ticking in hundredths of a second would overflow after that time. The fix was to restart the units regularly until a software update.

Exam use: shows that a fixed number of bits has a maximum, and overflow causes real faults.

Gangnam Style breaks YouTube's counter

In 2014 the video passed 2,147,483,647 views, the largest value a 32-bit two's complement integer can hold (2³¹ − 1). YouTube switched the counter to 64 bits.

Exam use: the range of a signed number is limited by the bits used. Positive values stop at 2ⁿ⁻¹ − 1.

Shifts for fast multiplication

Processors can multiply or divide by powers of two with a single shift, which is quicker than a full multiplication. Graphics and audio code use this often.

Exam use: say a left shift of n places multiplies by 2ⁿ, and mention what is lost when bits fall off.

Exam-style questions

Open each question for reminders, a model answer and common mistakes. Each underlined phrase earns one mark; the number shows which mark point it is.

Q1 Convert 2 marks Convert the binary number 10110101 into denary. Show your working.
ReminderWrite the place values (128 down to 1) above the bits. One mark for the method, one for the answer.
128 + 32 + 16 + 4 + 1 = 181
Common mistakeReading the place values left to right as 1, 2, 4 … The smallest value is on the right.
Q2 Convert 2 marks Convert the denary number 203 into hexadecimal.
ReminderDivide by 16 for the left digit, and the remainder is the right digit. Swap 10 to 15 for A to F.
203 ÷ 16 = 12 remainder 11, so C and B = CB
Common mistakeWriting 1211. Values above 9 must be a letter.
Q3 Give 2 marks Give two reasons why programmers use hexadecimal instead of binary.
ReminderGive two separate points. Each is about shorter, easier or fewer errors.
It is shorter, so fewer digits are needed to represent the same value (one hex digit is four bits). It is easier for humans to read, remember and copy, with fewer transcription errors.
Common mistakeSaying hex uses less memory or is faster for the computer. The computer still works in binary.
Q4 Explain 3 marks Two 8-bit registers hold 11001010 and 01101100. The values are added together. Explain what happens.
ReminderDo the addition. Count the bits in the answer. Name the error and its effect.
The sum is 100110110, which needs 9 bits. The register can store only 8 bits, so the ninth (carry) bit is lost. An overflow error occurs, and the stored value, 00110110 (54), is wrong.
Common mistakeJust writing "overflow" without saying why. Link it to the number of bits that fit.
Q5 Describe 3 marks A register holds 00010110. A logical right shift of two places is performed. State the new value, and describe the effect on the number.
ReminderShift all bits two places right, fill with 0s. Link to division by 4 and to the bits lost.
00000101 The value has been divided by 4 (from 22 to 5). The two bits that fell off the right (10) are lost, so the answer is truncated (5.5 would be 22 ÷ 4 exactly).
Common mistakeMoving the bits but keeping the old zeros on the left, giving a 6- or 7-bit answer. Always write 8 bits.
Q6 Show 3 marks Write −45 as an 8-bit two's complement binary number.
ReminderPositive version, flip, add 1. Check by adding the place values with −128.
45 = 00101101 Flip the bits: 11010010 Add 1: 11010011
Common mistakeFlipping without adding 1 (that gives −46). Or putting a 1 in front of the positive number.
Q7 Convert 4 marks The colour code #1E90FF is used on a web page. Write each pair of hex digits as an 8-bit binary number.
ReminderEach hex digit is one nibble. 1 = 0001, E = 1110, 9 = 1001, 0 = 0000, F = 1111.
1E = 00011110 90 = 10010000 FF = 11111111 Each hex digit converted to its own 4-bit nibble and joined in order, with leading zeros kept.
Common mistakeDropping the leading zeros in 0001 (writing 1E as 111110).

Top tips

  • Write the place values above the bits first. 128 64 32 16 8 4 2 1. It takes five seconds and avoids slips.
  • Always give 8 bits when the question says 8-bit, with leading zeros.
  • Check conversions by going back. Convert your binary answer to denary again.
  • Hex: work in nibbles. Never convert the whole byte at once.
  • Hex is for humans. Never say it saves memory or is faster for the computer.
  • Overflow answers need three things: the sum needs too many bits, the extra bit is lost, the stored value is wrong.
  • Shifts: left × 2ⁿ, right ÷ 2ⁿ, and a 1 falling off an end means an error or lost precision.
  • Two's complement: flip, add 1, and remember the left bit is −128. The range is −128 to 127.
