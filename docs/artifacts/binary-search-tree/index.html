Binary Search Tree Walkthrough

Every node's left subtree is smaller and its right subtree is bigger. Insert and search follow the same path: compare, then step left or right.

The big idea

A binary search tree keeps every node's left subtree smaller and its right subtree bigger. Searching halves the possibilities at every step, so a balanced tree of N nodes needs only about log₂ N comparisons.

Insert

Start at the root. If the new value is smaller go left, otherwise go right. Repeat until you reach an empty spot, then plant the new node there.

Search

Start at the root. Stop if it matches. If the target is smaller go left, if bigger go right. If you run off the tree into an empty spot (None), the value is not there.

Traversals

TraversalOrderUsed for
In-orderleft, node, rightOutput in ascending order
Pre-ordernode, left, rightCopying a tree
Post-orderleft, right, nodeDeleting a tree, evaluating expressions

Balanced tree

Search, insert and delete take O(log N) because each step discards about half of the remaining nodes.

Degenerate tree

If values arrive already in order, every node goes to the same side and the tree becomes a chain. Search then takes O(N).

Examples are explained in general terms.

  
Database indexes
Many databases keep an index in a tree-like structure so a record can be found in a handful of steps instead of scanning every row.
Use it for: why a tree makes search fast.

  
Autocomplete and spell check
Ordered structures let a program jump to the words that start with what you typed, rather than reading the whole dictionary.
Use it for: in-order traversal giving sorted output.

  
File systems
Folders contain other folders, a tree shape. Programs walk the tree to find, copy or delete files.
Use it for: pre-order and post-order traversals.

  
A sorted list that grows as data arrives
If new values keep arriving in order, a plain binary search tree degenerates into a chain, which is why balanced variants exist.

Q1 Describe 3 marks Describe how the value 45 is inserted into a binary search tree.

    
1. Start at the root and compare 45 with the value there.
2. If 45 is smaller follow the left pointer, if larger the right pointer, and repeat the comparison at each node.
3. When the pointer to follow is null (empty), create a new node holding 45 there and set the parent's pointer to it.

    
Common mistakeSaying the new node replaces an existing one. It always becomes a new leaf.

  
Q2 Write 2 marks State the output of an in-order traversal of the tree built from 50, 30, 70, 20, 40, 60, 80.

    
20 30 40 50 60 70 80 (ascending order). One mark for left, node, right order; one mark for the correct output.

  
Q3 Explain 4 marks Explain why searching a binary search tree can be faster than searching an unsorted list.

    
1. In an unsorted list every item may have to be checked, so N comparisons in the worst case.
2. In a binary search tree each comparison tells you to go left or right, discarding a whole subtree.
3. In a balanced tree this halves the remaining items each time, so about log₂ N comparisons.
4. This only holds if the tree is balanced; a degenerate tree is as slow as a list.
