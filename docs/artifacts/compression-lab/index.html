Concept 1

Why compress data?

Compression reduces the number of bits needed to store a file. A smaller file needs less storage space, uploads and downloads faster, and uses less bandwidth on the network.

The compression ratio compares sizes: original size ÷ compressed size. A 20 MB file squeezed to 5 MB has a ratio of 4:1.

Time = size in megabits ÷ speed in Mbps. 1 byte = 8 bits, so 120 MB is 960 megabits.

Concept 2

Lossy and lossless

Lossless

Compresses by finding patterns and storing them more efficiently. When you decompress, you get the exact original back. Nothing is thrown away.

Text, program code, documents, medical images. Formats: ZIP, PNG, FLAC.

Lossy

Permanently removes data the human eye or ear is unlikely to miss. Files get much smaller, but the original cannot be rebuilt.

Photos, music, video. Formats: JPEG, MP3, MP4.

Concept 3

Run length encoding (RLE)

RLE is a lossless method. Instead of storing every repeated value, store the value once with a count of how many times it repeats in a row. A run of the same value is a run.

AAAABBBCCD becomes 4A3B2C1D. Ten characters shrink to eight.

This page writes the count first, then the value. Data with long runs (simple images, icons, fax pages) compresses well. Data with no repeats gets bigger.

Concept 4

Huffman coding

Normally every character uses the same number of bits (ASCII uses 8). Huffman coding gives frequent characters short codes and rare characters long codes, so the whole message needs fewer bits. It is lossless.

The codes are found by building a binary tree:

  • Count how often each character appears.
  • Take the two lowest-frequency items and join them under a new node whose value is their sum.
  • Repeat with the new node included, until one node (the root) is left.
  • Label every left branch 0 and every right branch 1. A character's code is the path from the root down to it.

No code is ever the start of another code (a prefix code), so a stream of bits can only be read one way.
