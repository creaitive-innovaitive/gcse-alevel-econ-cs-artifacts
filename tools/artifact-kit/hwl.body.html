How a website appears on your screen

What happens between typing a web address and the page appearing: browser, DNS server, IP address, web server and HTML.

The big idea

When you type a web address, your browser asks a DNS server for the website's IP address, then asks the web server at that address for the page. The server sends back HTML files, and the browser renders them as the page you see.

The sequence

1. You type a URL, for example www.school-shoes.com, into the browser.

2. The browser sends the domain name to a DNS server.

3. If the DNS server has no record, it asks another DNS server, which returns the IP address.

4. The IP address is sent back to your computer.

5. Your computer contacts the web server at that IP address and requests the page using HTTP or HTTPS.

6. The web server sends the HTML files back, and the browser renders the page.

DNS server

Stores a database of domain names and their IP addresses. It never sends the web page.

Web server

Stores the website's files. It sends the page when it receives a request.

Examples are explained in general terms.

"Server not found"

If you mistype a domain name, no DNS server has a record for it. The IP address cannot be found, so the browser shows an error.

Use it for: what happens when DNS fails.

A slow website

The delay can come from any step: finding the IP address, contacting a busy web server, or sending large files back.

Use it for: describing the sequence in order.

Caching

A DNS server may store an IP address it has just received, so the next request for the same website is answered faster.

Use it for: why a DNS server stores a record it was given by another DNS server.

Q1 Describe 4 marks Describe how a web page is retrieved and displayed when a user enters a URL.
ReminderName the device doing each step: the browser, the DNS server and the web server.

1. The browser sends the domain name to a DNS server.

2. The DNS server finds the matching IP address (asking another DNS server if needed) and returns it.

3. The browser sends a request to the web server at that IP address.

4. The web server sends the HTML files back and the browser renders the page.

Common mistakeSaying the DNS server sends the web page. It only returns the IP address.
Q2 Explain 2 marks Explain why a computer needs DNS to turn a URL into an IP address.

1. Computers and web servers are identified on the network by IP addresses, not names.

2. People remember names better than numbers, so DNS translates the domain name into the IP address the computer needs.

Q3 Explain 2 marks Explain why a DNS server might store the IP address it receives from another DNS server.

1. It can answer the next request for the same domain itself (a cache).

2. This is quicker and avoids asking other DNS servers again.

Top tips

  • Say who does what. The browser asks, the DNS server looks up, the web server sends.
  • DNS returns an IP address, not the page.
  • Use the exact terms: domain name, IP address, web server, HTML, render.
  • Order matters. Name to DNS, IP back, request to web server, page sent back.
