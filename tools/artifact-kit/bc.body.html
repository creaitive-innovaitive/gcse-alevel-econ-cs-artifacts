Blockchain, Consensus and Cryptography

How transactions are grouped into blocks, linked by hashes, protected by proof of work and cryptography, and copied across many computers.

1 · The process of blockchaining

A blockchain is a decentralised digital ledger. Transactions are grouped into blocks, and each block is linked to the one before it using a hash. Once a block is added, it is very hard to change.

What is inside a block

Block 2 stores Block 1's hash. Change Block 1 and its hash changes, so Block 2's stored copy no longer matches. The break is visible straight away.

The process, step by step
  1. A user makes a transactionFor example, Lan sends 5 coins to Minh. Nobody hands over cash and no bank is involved.
  2. The transaction is signed with a private keyThis produces a digital signature that proves Lan authorised it. Only Lan has the private key.
  3. It is broadcast to the network of nodesNodes are the computers that hold a copy of the ledger. Each one receives the transaction.
  4. Nodes verify itThey check the signature is valid using Lan's public key, and that she has enough coins. Any invalid transaction (a forged signature, or coins the sender does not have) is rejected.
  5. Valid transactions are collected into a new blockA miner gathers pending transactions, adds a timestamp and the previous hash.
  6. The network reaches consensusNodes must agree who adds the next block. In proof of work miners race to solve a puzzle. The winner adds the block. See section 2.
  7. The block is hashed and linked to the chainIts hash is calculated from its contents, and the next block will store it as its previous hash.
  8. Every node updates its copy of the ledgerMinh now owns the 5 coins. The transaction is immutable: it cannot be altered without breaking the chain.
Try the hash: change one character
SHA-256 hash

Always the same length. The same input always gives the same hash. A tiny change gives a completely different hash. You cannot work backwards from the hash to the input.

3 · How cryptography works

Cryptography is the science of keeping data secret and checking it is genuine. Encryption scrambles plaintext into ciphertext using an algorithm and a key. Decryption reverses it.

Symmetric encryption

One shared key both encrypts and decrypts. Fast, but the key must reach the other person safely, and if it is stolen everything is exposed.

Example: AES, used to encrypt the actual data in a Wi-Fi connection or an encrypted phone.

Asymmetric encryption

A key pair. Anything locked with the public key can only be unlocked with the matching private key. The public key can be shared freely; the private key is never shared.

Example: RSA, used to set up HTTPS connections.

The padlock picture
1Minh publishes an open padlock (his public key) for anyone to use.
2Lan snaps the padlock shut on her message (encrypts with the public key).
3Only Minh's private key opens it. Even Lan cannot reopen the padlock.
4Digital signature is the reverse: Lan signs with her private key and everyone checks it with her public key. If it verifies, only Lan could have made it.
Try it: a Caesar cipher (the simplest symmetric cipher)
Ciphertext

Each letter moves along the alphabet by the key. Anyone who knows the key shifts back to decrypt. It is easy to crack because there are only 25 possible keys, which is why modern algorithms use enormously bigger keys.

2 · Proof of work: what the "work" really is

Proof of work means a miner has to spend real computer effort, and real electricity, before they are allowed to add a block. The effort is the proof. It makes cheating expensive and honest mining profitable.

So what is the work?

The work is guessing. The miner takes everything in the new block, adds one extra number called the nonce, and puts it all through the hash function. Out comes a hash. The network sets a rule, for example "the hash must start with 19 zeros". Almost every hash fails, so the miner changes the nonce by 1 and tries again.

Illustration only. Real hashes are 64 characters long and the winning nonce is far bigger.

Why guessing? A hash function cannot be run backwards, and it is impossible to predict which nonce will work. The only method is trial and error, exactly like rolling a die over and over until you get a six, except the odds are billions to one.

Hard to do, easy to check. Finding the winning nonce takes an enormous number of tries. Checking it takes one: every other node puts the block through the hash function once and sees whether it passes.

Why it keeps the network secure

To change an old block, a cheat would have to redo the work for that block and every block after it, faster than all the honest miners combined. That costs a fortune in electricity and hardware. To win they would need over half the network's power, a 51% attack. For Bitcoin that is too expensive to be realistic.

Why honest mining pays

A miner only earns the block reward if the network accepts their block. A cheating miner's invalid block is thrown away, and the electricity they spent is wasted. Following the rules is the profitable choice.

What miners actually use

Mining is done by software running on special hardware.

  • The software is connected to a full node. It gathers pending transactions, builds the candidate block and hands it to the hardware.
  • The hardware is an ASIC, a chip built to do one job only: hash. It is thousands of times faster than a normal computer at this, and useless for anything else.
  • When the hardware finds a valid nonce, the software broadcasts the block to the network.
  • Most people join a mining pool. Thousands of miners combine their power and share the reward according to how much work each did, so they earn small regular payments instead of a rare jackpot.
Difficulty: keeping the pace steady

Bitcoin is designed to produce one block about every 10 minutes. The difficulty is how hard the puzzle is: the more zeros required, the harder. Every 2,016 blocks (about two weeks) the network checks how fast blocks really arrived and adjusts.

What happenedBlocks arriveDifficulty changes
Lots of miners joinFaster than 10 minutesGoes up, so the puzzle is harder
Many miners leaveSlower than 10 minutesGoes down, so the puzzle is easier

Nobody decides this. The rule is built into the software every node runs.

How miners get paid
  • The winning miner adds a special first transaction that creates new coins for themselves. This is the block reward.
  • They also keep the transaction fees that users attached to get into the block.
  • The reward halves roughly every four years, an event called the halving. That is how Bitcoin reaches its 21 million limit.

Profit = reward + fees − costs. The costs are electricity, hardware, cooling and rent. Electricity is by far the biggest running cost, which is why where a miner sets up matters so much.

Real-world mining: why location decides profit

Good places for miners
  • Cheap electricity. The cheaper the power per unit, the more profit per coin mined.
  • Cold climate. Chips give off huge heat. Cool outside air means less spent on cooling.
  • Remote land. Cheap space, no noise complaints, and room to build near a power source.
  • Power that would be wasted. A wind farm in the middle of nowhere or a hydro dam sometimes produces more electricity than the local area can use. A miner can buy that surplus for very little, a form of stranded energy.
Bad places for miners
  • Cities. Electricity for homes and offices costs more, and grids are already busy.
  • High rent. Space in a city is expensive and a mining farm needs a lot of it.
  • Heat and noise. ASICs run day and night as loud as a vacuum cleaner or louder, and a hot room needs constant cooling.
  • Rules. Some places restrict or ban mining, or charge extra for heavy power use.

Why this also helps security.
  • Miners are spread over many countries, so no single government or power cut can shut the network down. When China banned mining, Bitcoin kept running, and its computing power recovered within months.
  • Cheap power means more miners can afford to take part, which raises the total work needed to attack the chain.
  • The trade-off is energy use. Critics point to mining powered by fossil fuels, while supporters say using surplus renewable power that would otherwise be wasted is a benefit.

Key term

A smart contract is a program stored on a blockchain that runs automatically when its conditions are met, for example releasing a payment when goods are confirmed delivered. Nobody can quietly change its rules once it is deployed.

Bitcoin BTC · PoW

The first cryptocurrency. Built to be peer-to-peer electronic cash without a bank. It is deliberately simple and conservative.

Pros
  • Longest track record and largest network, so it is very hard to attack
  • Fixed supply of 21 million, so no one can create more
  • Widely recognised as digital "gold" and accepted by many exchanges
Cons
  • Proof of work uses huge amounts of electricity
  • Slow (about 7 transactions a second) and fees rise when busy
  • Little support for smart contracts
  • Price swings widely, so it is a poor everyday payment tool

Real world: El Salvador made it legal tender in 2021, a policy that was later scaled back.

Ethereum ETH · PoS

A programmable blockchain. Developers write smart contracts that run on it, so it supports far more than payments.

Pros
  • Smart contracts enable DeFi (lending without banks), tokens and NFTs
  • Biggest developer community and most apps
  • Faster blocks than Bitcoin
  • Proof of stake cut its energy use by over 99%
Cons
  • Fees ("gas") can become very high when the network is busy
  • Smart-contract bugs can be exploited and cannot be easily undone
  • Scaling often relies on separate "layer 2" networks, which adds complexity
  • Staking favours those with lots of coins

Real world: stablecoins, digital collectibles and decentralised exchanges run on it.

Cardano ADA · PoS

A proof-of-stake platform designed around peer-reviewed research and formal methods, aiming for security and long-term sustainability.

Pros
  • Energy-efficient from the start, with no mining
  • Careful, research-led design aims to reduce errors
  • Low, predictable transaction fees
  • Staking is open to holders without locking coins away
Cons
  • Slower development, and smart contracts arrived years after Ethereum's
  • Smaller developer community and fewer apps
  • Less real-world usage, so its network effect is weaker

Real world: pilots for verifying qualifications and supply-chain records have been announced.

How to compare in the exam.
  • Bitcoin is money, Ethereum is a platform, Cardano is a research-led platform.
  • Bitcoin uses proof of work; Ethereum and Cardano use proof of stake.
  • Energy use, speed and smart contracts are the three easiest points of comparison.

Using blockchain in an answer

Digital currencies

Every payment is recorded in a block that is copied to many computers. Nobody has to trust a single bank, because everyone holds the same ledger.

Use it for: decentralised ledger, consensus and why tampering shows.

Tracking goods through a supply chain

Each step (made, shipped, delivered) can be recorded as a block. Because old blocks are hard to change, the record may be trusted by every company involved.

Use it for: a non-currency use of blockchain.

Mining and electricity

Proof of work needs a lot of computing effort, which uses a lot of electricity. This is one reason some blockchains use other consensus methods.

Use it for: evaluation: security against cost and energy use.

Q1 State 2 marks State two items stored in each block of a blockchain.

Any two from: transaction data; a timestamp; the hash of the block; the hash of the previous block; a nonce.

Q2 Explain 4 marks Explain why it is very hard to change a transaction in an old block of a blockchain.
ReminderUse a chain of reasoning: data changes, so the hash changes, so the next block no longer matches.

1. Changing the data in the block changes its hash.

2. The next block stores the previous hash, so it would no longer match.

3. Every later block would also have to be recalculated (and re-mined).

4. The blockchain is copied on many computers, so the changed copy would be rejected by the others.

Common mistakeSaying the data is "encrypted so it cannot be changed". The protection comes from hashes, links and many copies.
Q3 Describe 3 marks Describe what is meant by proof of work.

1. A miner has to spend real computing effort before it may add a block.

2. The miner repeatedly changes the nonce and calculates the hash until it meets the difficulty rule (for example enough leading zeros).

3. The effort makes cheating expensive, and other nodes can quickly check that the result is valid.

Top tips

  • Hash, not encryption. A hash is a fixed-length code made from data. It cannot be run backwards.
  • Chain of reasoning. Data changes, so the hash changes, so the next block's previous hash no longer matches.
  • Mention many copies. A decentralised ledger is copied across many computers.
  • Say what the nonce is for. Miners change it to get a different hash on each guess.
  • Know symmetric and asymmetric encryption. One shared key, or a public and private key pair.
