Graphs: Representation and Shortest Paths

A graph is a set of vertices joined by edges. It models maps, networks and relationships. Learn the vocabulary, build adjacency matrices and lists, trace Dijkstra's shortest path algorithm, and see exactly how graphs turn up in the exam.

The big idea

A graph is an abstract data type made of vertices (also called nodes) and edges (also called arcs) that connect pairs of vertices. Unlike a list or a tree, a graph has no fixed shape: any vertex can connect to any other, and loops are allowed. That freedom is why graphs model real networks so well.

The vocabulary

TermMeaning
Vertex (node)A point in the graph, e.g. a town, a person, a web page.
Edge (arc)A connection between two vertices, e.g. a road, a friendship, a link.
Undirected graphEdges work both ways. A to B also means B to A.
Directed graph (digraph)Each edge has a direction, drawn as an arrow. A to B does not mean B to A.
Weighted graphEach edge has a value (cost): distance, time, price, capacity.
AdjacentTwo vertices joined directly by an edge are neighbours.
PathA sequence of vertices where each consecutive pair is joined by an edge.
CycleA path that starts and ends at the same vertex.
Connected graphThere is a path between every pair of vertices.
DegreeThe number of edges at a vertex (undirected graphs).
Graph or tree?A tree is a special graph: connected, with no cycles, and with a root. Every tree is a graph, but most graphs are not trees.

Storing a graph

A graph is an abstract idea, so it must be implemented with something concrete. The two standard ways are an adjacency matrix and an adjacency list. Both describe the same graph below.

Adjacency matrix

A 2D array with one row and one column per vertex. Cell [row][column] holds 1 (or the weight) if there is an edge from the row vertex to the column vertex, and 0 (or blank) if not.

  • Undirected graph: the matrix is symmetric.
  • Checking for one edge: a single lookup.
  • Always n × n cells, even if there are few edges.

Adjacency list

For each vertex, a list of the vertices it connects to (with weights if weighted). Often a dictionary of lists, or an array of linked lists.

  • Uses memory only for edges that exist.
  • Easy to list all neighbours of a vertex.
  • Checking for one edge means searching that vertex's list.

Shortest paths: Dijkstra's algorithm

On a weighted graph, Dijkstra's algorithm finds the shortest (lowest total weight) path from a start vertex to every other vertex. It keeps a table of the best known distance to each vertex, repeatedly picks the unvisited vertex with the smallest distance, and uses it to improve its neighbours' distances. The edge weights must not be negative. This is in section 19.2, but you cannot trace it without understanding the graph, so it is covered here.

A* in one paragraph

A* is Dijkstra with a guide. For each vertex it also uses a heuristic h, an estimate of the remaining distance to the goal (for example the straight-line distance on a map). It picks the vertex with the lowest f = g + h, where g is the distance travelled so far. A good heuristic means A* explores far fewer vertices than Dijkstra, and still finds the shortest path if h never over-estimates.

6 · Multiple choice

Descriptions are kept general. Use them as examples of ideas, not as exact descriptions of any company's software.

Satnav and maps (weighted)

Junctions are vertices, roads are edges, and the weights are distance or expected travel time. Finding a route is a shortest-path problem. One-way streets make the graph directed.

Exam use: the classic weighted-graph example. Say what the vertices, edges and weights represent.

Social networks (undirected and directed)

People are vertices. A mutual friendship is an undirected edge. "Following" someone is a directed edge, because following back is a separate edge.

Exam use: the clearest way to explain directed against undirected edges.

Links between web pages (directed)

Each page is a vertex and each hyperlink is a directed edge. Search engines analyse this graph to judge how important a page is.

Exam use: a huge sparse graph, so an adjacency list is more sensible than a matrix.

Network routing (weighted)

Routers are vertices and links are edges weighted by cost or delay. Routing protocols use shortest-path ideas like Dijkstra's to choose how packets travel.

Exam use: links 19.1.3 to the Chapter on networks, and shows why weights matter.

Course or task dependencies (directed)

If you must pass course A before course B, draw an edge from A to B. The graph shows a valid order in which to take everything. It must have no cycles.

Exam use: an example where direction carries meaning and a cycle would be an error.

Games and puzzles

Each board position is a vertex, and each legal move is an edge to the next position. A* is widely used to find paths for characters in games, using straight-line distance as the heuristic.

Exam use: a concrete context for A* and its heuristic.

Four things examiners reward

  • Use the scenario words. "The vertices are bus stops, the edges are routes, the weights are journey times" beats a generic definition.
  • Say which way round the matrix reads. Row is the start vertex, column is the end vertex. It matters for directed graphs.
  • Show Dijkstra working. A table with a row per step earns method marks even if the final distance is wrong.
  • Justify structure choices with size. Sparse graph, so list. Dense graph or many edge checks, so matrix.
Dijkstra and negative weightsDijkstra's algorithm assumes no negative edge weights. If a question gives a negative weight, say that the algorithm is not suitable.

Exam-style questions

Open each question for reminders, a model answer and common mistakes. Each coloured phrase earns one mark; the number shows which mark point it is.

Q1 State 2 marks State what is meant by a graph.
ReminderTwo parts: the things, and the connections between them.
A graph is an abstract data type made up of a set of vertices (nodes) that are connected by edges (arcs); edges may be directed and may have weights.
Common mistakeDescribing a bar chart or line graph. In computer science, a graph is the data structure.
Q2 Describe 3 marks Describe the difference between a directed graph and an undirected graph. Give an example of data that suits each.
ReminderOne difference, then two examples.
In a directed graph each edge has a direction, so an edge from A to B does not mean there is an edge from B to A; in an undirected graph an edge works in both directions. Directed: web page links, or one-way streets. Undirected: mutual friendships, or two-way roads.
Common mistakeGiving examples without saying why. Link the example to direction: following someone is one-way.

Q5 Explain 3 marks A graph of 10,000 web pages has about 30,000 links. Explain why an adjacency list is more suitable than an adjacency matrix.
ReminderUse the numbers. Compare the memory each one needs.
A matrix needs 10,000 × 10,000 = 100 million cells, however few edges there are. With only about 30,000 links, nearly all of those cells would be 0, so the graph is sparse and the matrix wastes memory. An adjacency list stores only the 30,000 edges that exist, so it needs far less memory.
Common mistakeSaying lists are "faster" in general. For checking one edge a matrix is faster.

Q7 Describe 4 marks Describe how Dijkstra's algorithm finds the shortest path from a start vertex to a destination.
ReminderInitialise, choose, update, repeat, read the route.
The distance to the start vertex is set to 0 and every other vertex to infinity; no vertex is visited. The unvisited vertex with the smallest distance is chosen and marked as visited. For each unvisited neighbour, the distance through the chosen vertex is calculated; if it is smaller than the stored distance, the distance and the previous vertex are updated. This repeats until the destination is visited; the path is found by following the previous vertices back from the destination.
Common mistakeDescribing a "greedy" jump to the nearest neighbour only. Distances are stored and can be improved later.
Q8 Explain 4 marks A bus company wants to store its network of 40 stops so that the quickest route between any two stops can be found. Explain how a graph could be used.
ReminderSay what the vertices, edges and weights stand for, then how it is used and stored.
Each bus stop is a vertex. Each route between two neighbouring stops is an edge; it is directed if buses only run one way. Each edge is weighted with the journey time, so the quickest route is the path with the lowest total weight. The graph can be stored as an adjacency list or matrix, and an algorithm such as Dijkstra's can find the quickest route.
Common mistakeLeaving out the weights. Without them there is no way to say which route is quickest.
Q9 Explain 3 marks Explain how the A* algorithm differs from Dijkstra's algorithm.
ReminderHeuristic, how it chooses the next vertex, and the benefit.
A* uses a heuristic, an estimate of the distance from each vertex to the goal. It chooses the next vertex using the lowest f = g + h, the distance so far plus the estimate, whereas Dijkstra's only uses the distance so far. A good heuristic lets A* head towards the goal and explore fewer vertices, so it is usually faster.
Common mistakeSaying A* "always finds a different path". It finds the shortest path as long as the heuristic never over-estimates.
Q10 Write 4 marks A graph is stored as a Python dictionary where each key is a vertex and each value is a list of its neighbours, e.g. {"A": ["B", "C"], "B": ["C"], "C": ["D"], "D": []}. Write a function edge_count(graph) that returns the number of edges in a directed graph.
ReminderEach list entry is one directed edge. Loop through the vertices and add up the lengths.
def edge_count(graph):
    total = 0                       # (1) accumulator
    for vertex in graph:            # (2) loop through vertices
        total += len(graph[vertex]) # (3) add that vertex's edges
    return total                    # (4) return the total

Total initialised to 0. Loop through every vertex. Add the number of neighbours of each vertex. Return the total. (For an undirected graph stored this way, each edge appears twice, so divide by 2.)

Common mistakeCounting vertices, or forgetting that an undirected edge is stored in two lists.

Top tips

  • Know the words. Vertex or node, edge or arc, directed, undirected, weighted. Use the exact terms.
  • Row is from, column is to. Write that on your answer. An undirected matrix is symmetric; a directed one need not be.
  • Count the 1s. Undirected: 2 per edge. Directed: 1 per edge. It is a quick check.
  • Matrix or list? Compare the sizes. n × n cells against the number of edges.
  • Dijkstra: one row per vertex finished. Cross out finished vertices, update only if smaller, and follow Prev back for the path.
  • Never finish a vertex early. The vertex with the smallest unfinished distance is always the next one.
  • A* = Dijkstra + a heuristic. f = g + h. Mention that h must not over-estimate.
  • A tree is a graph with no cycles. Do not mix them up in definitions.
  • In a scenario, name the vertices, edges and weights. It is the quickest marks.
